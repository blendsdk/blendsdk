Overview ​

BlendSDK is designed with a modular architecture, empowering developers to use only what they need while ensuring cohesive integration and high maintainability. This page provides a detailed look into its architecture, design patterns, and how you can leverage these components to build powerful and scalable applications.

Modular Architecture ​

BlendSDK employs a modular architecture, allowing developers to integrate only the packages necessary for their projects. This ensures that applications remain lean and efficient, without unnecessary code. The modular nature of BlendSDK facilitates easier maintenance and updates, and each package is designed to operate independently, yet cohesively when combined.

Key Design Patterns ​

BlendSDK incorporates key design patterns that enhance its functionality and usability:

  • Builder Pattern: Used widely for setting up complex configurations, such as in the blendsdk/cmdline for constructing command configurations.
  • Dependency Injection (DI) Pattern: Implemented in blendsdk/webafx, which manages service dependencies through a service container.
  • Plugin Architecture: Extends functionality in blendsdk/webafx with customizable plugins for logging, caching, and more.
  • Strategy Pattern: Utilized in blendsdk/dbcore and blendsdk/cmdline to allow various query operations or command validations.
  • Repository Pattern: Ensures clean separation between data access logic and business logic, particularly seen in blendsdk/postgresql.

Package Composition ​

BlendSDK packages are designed to work seamlessly together. For example, a realistic application might integrate blendsdk/webafx for a web server, blendsdk/postgresql for database operations, and blendsdk/webafx-cache for caching and pub/sub capabilities. Here’s a basic setup using these packages:

typescript
import { WebApplication } from 'blendsdk/webafx';
import { PostgreSQLDatabase } from 'blendsdk/postgresql';
import { RedisCacheProvider } from 'blendsdk/webafx-cache';

// Set up web application
const app = new WebApplication();
const database = new PostgreSQLDatabase({ host: 'localhost', user: 'username', password: 'password', database: 'example' });
const cache = new RedisCacheProvider({ host: 'localhost', port: 6379 });

app.use(database);
app.use(cache);

// Start the application
async function start() {
    await app.start();
    console.log('Application is running...');
}

start().catch(console.error);

Single-Package Distribution ​

BlendSDK follows a single-package distribution system, using the blendsdk/* namespace format for imports instead of scoped packages (e.g., blendsdk/*). This simplifies the import paths and makes it easier to manage dependencies across the ecosystem.

Realistic Application Architecture Example ​

Consider an enterprise-level application that needs to handle user authentication, data caching, and database management:

typescript
import { WebApplication } from 'blendsdk/webafx';
import { JwtAuthProvider } from 'blendsdk/webafx-auth';
import { PostgreSQLDatabase } from 'blendsdk/postgresql';
import { RedisCacheProvider, RedisPubSubProvider } from 'blendsdk/webafx-cache';

// Initialize components
const app = new WebApplication();
const authProvider = new JwtAuthProvider({ secret: 'your-jwt-secret' });
const database = new PostgreSQLDatabase({ host: 'db.example.com', database: 'app_db', user: 'db_user', password: 'password' });
const cache = new RedisCacheProvider({ host: 'redis.example.com' });
const pubSub = new RedisPubSubProvider({ host: 'redis.example.com' });

// Register components
app.use(authProvider);
app.use(database);
app.use(cache);
app.use(pubSub);

// Start application
(async () => {
    await app.start();
    console.log('Application is running...');
})().catch(console.error);
