i18n Overview ​

What It Is ​

blendsdk/i18n is a runtime-agnostic internationalization (i18n) library designed for applications built with the BlendSDK. It provides robust support for translation management, enabling developers to easily implement multilingual capabilities in their applications.

Key Features ​

  • Translator: Facilitates translation lookup with locale fallback, pluralization support, and string interpolation using parameters.
  • Pluggable TranslationSource Interface: Allows integration with various translation backends.
  • Built-In Sources: Includes JsonFileSource for JSON files and ContentFileSource for file types such as HTML, Markdown, and plain text.
  • Merge Functionality: Merges multiple translation catalogs, prioritizing the most recent entries.
  • Locale Fallback: Automatically falls back from specific locales (e.g., en_GB to en).
  • Robust Error Handling: Provides clear error messages for missing translations and file access issues.

When To Use ​

Use blendsdk/i18n in scenarios where you need to:

  • Support multiple languages in your web applications.
  • Load translations from various sources (files, APIs, etc.).
  • Manage dynamic content with placeholders for user-specific data (e.g., names, counts).
  • Implement pluralization based on numeric values in translations.
  • Ensure a smooth developer experience with clear structure and robust features.

Architecture ​

The architecture of blendsdk/i18n follows established design patterns:

  • Strategy Pattern: Allows for different translation sources to be used interchangeably.
  • Factory Pattern: This is used to create instances of translation sources based on specified configurations.
  • Mediator Pattern: Facilitates communication between different components like the Translator and TranslationSource.

This modular approach enables ease of integration, testing, and maintenance.

Dependencies ​

  • Peer Dependencies: None specific to this package.
  • Direct Dependencies:
    • blendsdk/stdlib for utility functions.

blendsdk/i18n is designed to be self-contained and is independent of other libraries, relying solely on the functionality provided by blendsdk/stdlib for utility operations.

Minimum Example ​

Here is a brief example demonstrating basic usage of the blendsdk/i18n package:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello ${name}', nl: 'Hallo ${name}' },
        farewell: { en: 'Goodbye', nl: 'Tot ziens' },
    },
});

const message = translator.translate('greeting', 'en', { name: 'Alice' });
console.log(message); // Output: Hello Alice

i18n Core Concepts ​

Translator ​

What It Is ​

The Translator class serves as the core component of the internationalization library, providing methods to translate keys based on the specified locale. It supports locale fallback, pluralization, and parameter interpolation.

How It Works ​

The Translator maintains a catalog of translations mapped by keys and locales. When translating a key, it first checks for an exact locale match, then falls back to the language-level match if necessary. It also handles plural forms based on provided count parameters, using tuple structures for singular and plural versions.

Complete Example ​

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello ${name}', nl: 'Hallo ${name}' },
        book: { en: ['${count} book', '${count} books'] },
    },
});

const greetingMessage = translator.translate('greeting', 'en', { name: 'Alice' });
console.log(greetingMessage); // Output: Hello Alice

const bookMessage = translator.translate('book', 'en', { count: 5 });
console.log(bookMessage); // Output: 5 books

TranslationSource Interface ​

What It Is ​

The TranslationSource interface defines a contract for loading translation data from different sources, such as JSON files, content files, or remote APIs. It allows for easy integration of various translation backends.

How It Works ​

Implementations of the TranslationSource interface must provide a method to load translation data and return it in the form of a TranslationCatalog. This design allows multiple sources to be merged into a single catalog, enhancing flexibility.

Complete Example ​

typescript
import { JsonFileSource } from 'blendsdk/i18n-node';

const source = new JsonFileSource({
    paths: ['./translations/*.json'], // Load all JSON files in the specified directory.
});

const catalog = await source.load();
console.log(catalog);

mergeCatalogs ​

What It Is ​

The mergeCatalogs function is a utility to combine multiple TranslationCatalog objects into one, allowing for a layered approach to translation management.

How It Works ​

It iterates through the provided catalogs and merges them. If duplicate keys exist, the values from later catalogs will override those from earlier ones, ensuring predictable precedence.

Complete Example ​

typescript
import { mergeCatalogs } from 'blendsdk/i18n';
import type { TranslationCatalog } from 'blendsdk/i18n/types';

const baseCatalog: TranslationCatalog = {
    greeting: { en: 'Hello', nl: 'Hallo' },
};

const overrideCatalog: TranslationCatalog = {
    greeting: { en: 'Hi' },
};

const mergedCatalog = mergeCatalogs([baseCatalog, overrideCatalog]);
console.log(mergedCatalog);
// Output: { greeting: { en: 'Hi', nl: 'Hallo' } }

ContentFileSource ​

What It Is ​

ContentFileSource is a translation source that loads translations from content files, following a specific file naming convention to extract locale and keys.

How It Works ​

It reads files based on configured directory paths and filters them according to the specified file extensions. Each file's name must conform to the &lt;locale&gt;.&lt;key&gt;.&lt;ext&gt; format, which allows the source to parse and load translations effectively.

Complete Example ​

typescript
import { ContentFileSource, contentFileSource } from 'blendsdk/i18n-node';

const source = contentFileSource({
    paths: ['./content/emails'],
    extensions: ['.html', '.md'],
});

const catalog = await source.load();
console.log(catalog);

JsonFileSource ​

What It Is ​

JsonFileSource is a translation source that loads translations from JSON files. It supports both multi-locale and single-locale formats.

How It Works ​

It reads JSON files specified in the configuration and auto-detects their format. The loaded translations are normalized into a TranslationCatalog, which can then be used for translation.

Complete Example ​

import { JsonFileSource } from 'blendsdk/i18n-node';

    paths: ['./translations/*.json'], // Load all JSON files in the specified path.
});

Through its modular architecture and flexible design, the blendsdk/i18n package empowers developers to implement robust internationalization features in their applications. The combination of various translation sources, a powerful translator, and seamless integration ensures that your multi-language needs are catered to effectively.

import { Translator } from 'blendsdk/i18n';

console.log(translator.translate('greeting', 'nl')); 
// Output: greeting (returns the key as falls back)

The Translator can handle pluralization based on the count parameter, enabling different translations for singular and plural forms.

console.log(translator.translate('book', 'en', { count: 1 }));
// Output: 1 book

console.log(translator.translate('book', 'en', { count: 5 }));

When handling translations, the Translator provides clear error handling patterns, including notifying when a translation key is missing or if locale-specific translations are unavailable.

Handling Missing Translations ​

You can define a custom onMissingTranslation callback to handle cases where a translation key is not found:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        greeting: { en: 'Hello', nl: 'Hallo' },
    },
    onMissingTranslation: (key, locale) => {
        console.warn(`Missing translation for ${key} in ${locale}`);
    }
});

console.log(translator.translate('unknown_key', 'en')); 
// Output: unknown_key (with a warning logged)

Errors from JSON or file sources would throw exceptions detailing the issues for better debugging. Ensure to wrap loading calls in try/catch blocks to handle these potential errors gracefully.

typescript
import { JsonFileSource } from 'blendsdk/i18n-node';

async function loadTranslations() {
    const source = new JsonFileSource({
        paths: ['./translations/*.json']
    });

    try {
        const catalog = await source.load();
        console.log(catalog);
    } catch (error) {
        console.error('Error loading translations:', error);
    }
}

loadTranslations();

i18n Advanced Patterns ​

Combining Multiple Translation Sources with Merging ​

When to Use ​

This pattern is useful when you need to manage translations from different sources, such as JSON files for static translations and dynamic content files, and want to ensure that later sources override earlier ones for flexibility.

Complete Example ​

typescript
import { mergeCatalogs } from 'blendsdk/i18n';
import { JsonFileSource } from 'blendsdk/i18n-node';
import { ContentFileSource } from 'blendsdk/i18n-node';

async function loadTranslations() {
    const jsonSource = new JsonFileSource({
        paths: ['./translations/*.json'],
    });

    const contentSource = new ContentFileSource({
        paths: ['./content/emails'],
        extensions: ['.html'],
    });

    const [jsonCatalog, contentCatalog] = await Promise.all([
        jsonSource.load(),
        contentSource.load(),
    ]);

    const mergedCatalog = mergeCatalogs([jsonCatalog, contentCatalog]);
    return mergedCatalog;
}

loadTranslations().then((catalog) => {
    console.log(catalog);
});

Why This Pattern is Valuable ​

Combining multiple sources into a single catalog allows for a layered approach to translation management. This is particularly valuable in large applications where you might have common translations in JSON files for reusability and specific translations in content files for more dynamic content.

Caveats or Performance Considerations ​

  • Performance: The merging of catalogs may introduce overhead, especially if the catalogs are large, so it's wise to consider caching strategies where possible.
  • Overriding Conflicts: Care should be taken when keys overlap; late sources will override early sources. Ensure that the order of sources is intentional.

Dynamic Language Switching with State Management ​

When to Use ​

This pattern is ideal when you want to allow users to switch languages dynamically without needing to reload the entire page, for instance in Single Page Applications (SPAs).

Complete Example ​

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello', nl: 'Hallo' },
    },
});

let currentLocale = 'en';

function setLocale(locale: string) {
    currentLocale = locale;
}

function translate(key: string) {
    return translator.translate(key, currentLocale);
}

// Sample UI interaction
function updateGreeting() {
    const greeting = translate('greeting');
    console.log(greeting); // Outputs greeting based on currentLocale
}

// User switches to Dutch
setLocale('nl');
updateGreeting(); // Output: Hallo

Why This Pattern is Valuable ​

Dynamically switching between languages offers a better user experience and can be essential for accessibility, allowing users to interact with the application in their preferred language instantly.

Caveats or Performance Considerations ​

  • Catalog Reloading: You might need to reload the catalog if switching languages requires new translations that are not currently loaded.
  • State Management: In more complex applications, leveraging state management solutions (like Redux or Context API in React) may be beneficial for maintaining the current locale across the app.

Advanced Pluralization Handling ​

When to Use ​

Use this pattern when your application requires robust pluralization rules based on different languages’ specific pluralization rules, especially for languages like Arabic or Russian, where plural rules differ significantly.

Complete Example ​

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        itemCount: {
            en: ['1 item', '${count} items'], // Pluralization in English
            ru: ['1 предмет', '${count} предмета', '${count} предметов'], // Pluralization in Russian
        },
    },
});

function getItemCountMessage(count: number, locale: string) {
    const countMessage = translator.translate('itemCount', locale, { count });
    console.log(countMessage);
}

// Display messages for different counts
getItemCountMessage(1, 'en'); // Output: 1 item
getItemCountMessage(5, 'en'); // Output: 5 items
getItemCountMessage(1, 'ru'); // Output: 1 предмет

Why This Pattern is Valuable ​

Handling pluralization correctly ensures that translations are contextually appropriate, enhancing the quality of user experience and maintaining grammatical correctness in languages that have complex rules around plural forms.

Caveats or Performance Considerations ​

  • Complexity in Catalog Management: Ensure that your translation catalog maintains clear distinctions for plural rules to avoid conflicts and confusion.
  • Localization Oversight: Always review pluralization rules for the languages you're supporting, as they can vary widely and affect the translation quality.

Implementing Fallback Strategies for Missing Translations ​

When to Use ​

This pattern is beneficial when you want to provide graceful degradation for cases where translations may be missing by falling back to a default language or showing the key instead.

Complete Example ​

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello', nl: 'Hallo' },
    },
    onMissingTranslation: (key, locale) => {
        console.warn(`Missing translation for ${key} in ${locale}`);
    }
});

// Attempt to translate a missing key
const farewell = translator.translate('farewell', 'nl'); // Output: farewell (key returned as-is)

// Display fallback warning
console.log(farewell); // This will also log that the translation is missing

Why This Pattern is Valuable ​

Implementing fallback strategies ensures that your application does not present users with errors due to missing translations and instead provides a more graceful handling strategy. Logging missing translations also aids in localization improvements.

Caveats or Performance Considerations ​

  • User Perception: Displaying keys instead of meaningful translations can confuse users. Consider how best to present fallback content.
  • Monitoring Missing Translations: Regularly track and resolve missing translations when building your localization files to reduce reliance on fallback scenarios.

Built-In Plugins for Content Loading ​

When to Use ​

This pattern is helpful when working with larger applications that rely on modular translation sources, allowing for easier management, loading, and updating of translations as content changes.

Complete Example ​

typescript
import { createI18nPlugin } from 'blendsdk/i18n-node';
import { contentFileSource } from 'blendsdk/i18n-node';
import { jsonFileSource } from 'blendsdk/i18n-node';

// Set up plugin with multiple sources
const i18nPlugin = createI18nPlugin({
    sources: [
        contentFileSource({ paths: ['./content'] }),
        jsonFileSource({ paths: ['./translations/*.json'] }),
    ],
});

async function initialize() {
    await i18nPlugin.load();

    // Your app logic with translations accessible here
}
initialize();

Why This Pattern is Valuable ​

Using plugins to manage translation sources allows for cleaner integration with frameworks and encapsulation of translation logic, making maintenance and updates easier and reducing boilerplate code.

Caveats or Performance Considerations ​

  • Loading Performance: Ensure to cache loaded translations efficiently to enhance performance when dynamically loading multiple sources.
  • Compatibility: Make sure your plugins are compatible with the structure and formats expected by your translation sources to prevent errors during the merging process.

i18n Best Practices ​

Do / Don't Pairs ​

1. Using Correct Locale Fallback ​

❌ Don't:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        greeting: { en: "Hello, ${name}", fr: "Bonjour, ${name}" },
    },
});

console.log(translator.translate('greeting', 'fr_CA')); // Output: greeting (key returned as-is)

Problem: The fr_CA locale is not defined; it falls back to returning the key, not a defined translation.

✅ Do:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        greeting: { en: "Hello, ${name}", fr: "Bonjour, ${name}" },
    },
});

console.log(translator.translate('greeting', 'fr')); // Output: Bonjour, ${name}

Why This Works: The fr locale is defined, allowing for correct fallback behavior, enhancing user experience by providing an appropriate translation.

2. Avoiding the Use of any Type ​

❌ Don't:

typescript
import { Translator } from 'blendsdk/i18n';

const catalog: any = {
    greeting: { en: "Hello, ${name}", nl: "Hallo, ${name}" },
};

const translator = new Translator({ catalog });

Problem: Using any for catalog leads to the loss of type safety, potentially causing runtime errors.

✅ Do:

typescript
import { Translator, TranslationCatalog } from 'blendsdk/i18n';

const catalog: TranslationCatalog = {
    greeting: { en: "Hello, ${name}", nl: "Hallo, ${name}" },
};

const translator = new Translator({ catalog });

Why This Works: Defining the TranslationCatalog type ensures structure and type safety, catching potential issues at compile-time.

3. Handling Pluralization Correctly ​

❌ Don't:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        itemCount: { en: "Item Count: ${count}", nl: "Aantal: ${count}" },
    },
});

console.log(translator.translate('itemCount', 'en', { count: 2 })); // Output: Item Count: 2

Problem: Fails to differentiate between singular/plural forms.

✅ Do:

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        itemCount: { 
            en: ["Item Count: ${count} item", "Item Count: ${count} items"],
            nl: ["Aantal: ${count} item", "Aantal: ${count} items"]
        },
    },
});

console.log(translator.translate('itemCount', 'en', { count: 2 })); // Output: Item Count: 2 items

Why This Works: Using an array allows handling different forms based on the count parameter, thus providing a more natural language translation.

4. Efficiently Merging Translations ​

❌ Don't:

typescript
import { mergeCatalogs } from 'blendsdk/i18n';

const firstCatalog = { greeting: { en: "Hello" } };
const secondCatalog = { greeting: { en: "Hi" } };

const merged = mergeCatalogs([firstCatalog, secondCatalog]);
console.log(merged); // Output may be confusing and lose definitions.

Problem: When defined keys overlap, late definitions override early ones without structure, potentially losing important translations.

✅ Do:

typescript
import { mergeCatalogs } from 'blendsdk/i18n';

const baseCatalog = { greeting: { en: "Hello", nl: "Hallo" } };
const overrideCatalog = { greeting: { en: "Hi" } };

const merged = mergeCatalogs([baseCatalog, overrideCatalog]);
console.log(merged); // Output: { greeting: { en: "Hi", nl: "Hallo" } }

Why This Works: Clearly structured merging retains necessary translations while allowing for predictable overrides by maintaining defined keys across catalogs.

5. Asynchronous Loading with Error Handling ​

❌ Don't:

typescript
import { JsonFileSource } from 'blendsdk/i18n-node';

const source = new JsonFileSource({
    paths: ['./translations/*.json'],
});

const catalog = await source.load(); // No error handling

Problem: If the source fails to load (e.g., files do not exist), your application will crash without error handling.

✅ Do:

typescript
import { JsonFileSource } from 'blendsdk/i18n-node';

const source = new JsonFileSource({
    paths: ['./translations/*.json'],
});

try {
    const catalog = await source.load();
    console.log(catalog);
} catch (error) {
    console.error('Failed to load translations:', error);
}

Why This Works: Wrapping asynchronous operations in try/catch blocks gives you control over error handling, allowing for graceful degradation.

Anti-Patterns ​

1. Using Hardcoded Strings for Translations ​

Hardcoding strings directly in your application code leads to maintenance challenges and poor localization support. Always use translation catalogs or resources.

2. Ignoring Locale Structure in Translations ​

Failing to pay attention to locale-specific grammar and structure can result in awkward or incorrect translations. Always consult native speakers for complex languages.

3. Assuming All Users Speak the Default Language ​

Applications should not assume a single language for all users; dynamically loading and switching languages is crucial for inclusivity.

Performance Tips ​

1. Cache Translations ​

Load translations once at application startup or cache them to improve performance when switching languages frequently.

2. Optimize Catalog Loading ​

Consider lazy loading or grouping translations into larger files to reduce the number of file reads and speed up your application’s loading times.

3. Enable Validations ​

Implement validation checks on your translation files and catalog structures to ensure they are loaded correctly—this helps avoid runtime issues.

Security Considerations ​

1. Protect Translation Files ​

Ensure that translation files are not publicly accessible as they might expose sensitive information or internal structure.

2. Validate Input Data ​

When using user inputs for translations (such as dynamic parameters in strings), always validate and sanitize them to prevent injection attacks.

3. Avoid Denial of Service (DoS) ​

Prevent overloading your translation service by implementing rate limits for the translation requests, ensuring the service remains responsive under heavy load.

i18n Common Scenarios ​

How do I create a basic Translator instance? ​

To create a basic Translator instance, you need to define the default locale and a catalog of translations.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello', nl: 'Hallo' },
        farewell: { en: 'Goodbye', nl: 'Tot ziens' },
    },
});

console.log(translator.translate('greeting', 'en')); // Output: Hello

How do I translate a string with parameters? ​

You can pass parameters as an object to the translate method for dynamic content within the string.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello, ${name}', nl: 'Hallo, ${name}' },
    },
});

const message = translator.translate('greeting', 'en', { name: 'Alice' });
console.log(message); // Output: Hello, Alice

How do I handle missing translations? ​

You can provide an onMissingTranslation callback in your Translator configuration to handle cases where a translation key is not found.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    catalog: {
        greeting: { en: 'Hello', nl: 'Hallo' },
    },
    onMissingTranslation: (key, locale) => {
        console.warn(`Missing translation for ${key} in ${locale}`);
    }
});

const farewell = translator.translate('farewell', 'en'); // Output: farewell (logs warning)
console.log(farewell);

How do I implement locale fallback? ​

The Translator class automatically handles locale fallback, allowing for broader language support when specific locales are missing.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello', en_GB: 'Hello, mate' },
    },
});

console.log(translator.translate('greeting', 'en_GB')); // Output: Hello, mate
console.log(translator.translate('greeting', 'fr')); // Output: greeting (returns the key as the fallback)

How do I use pluralization? ​

You can manage plural forms by using an array format in your catalog for keys expected to have singular and plural versions.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        itemCount: { 
            en: ['1 item', '${count} items'],
            nl: ['1 item', '${count} items']
        },
    },
});

console.log(translator.translate('itemCount', 'en', { count: 2 })); // Output: 2 items

How do I merge multiple translation catalogs? ​

Use the mergeCatalogs function to combine multiple translation catalogs into one, ensuring that later sources override earlier ones.

typescript
import { mergeCatalogs } from 'blendsdk/i18n';

const baseCatalog = { greeting: { en: 'Hello', nl: 'Hallo' } };
const overrideCatalog = { greeting: { en: 'Hi' } };

const mergedCatalog = mergeCatalogs([baseCatalog, overrideCatalog]);
console.log(mergedCatalog); // Output: { greeting: { en: 'Hi', nl: 'Hallo' } }

How do I load translations from JSON files? ​

You can load translations from JSON files using the JsonFileSource, which allows for flexible configuration of file paths.

i18n Troubleshooting ​

Common Errors ​

Invalid JSON file format ​

Error Message / Symptom: Failed to parse JSON file "file-path": Unexpected token ...

Cause: This error occurs when the JSON file has an invalid format, which makes it unreadable by the JSON parser.

Fix: Ensure that the JSON file is properly formatted. A valid JSON structure should not have trailing commas, should use double quotes for keys and string values, and must follow correct JSON syntax.

typescript
import { JsonFileSource } from 'blendsdk/i18n-node';

const source = new JsonFileSource({
    paths: ['./translations/*.json'],
});

try {
    const catalog = await source.load();
    console.log(catalog);
} catch (error) {
    if (error instanceof Error) {
        console.error(`Failed to parse JSON: ${error.message}`);
    }
}

Missing translation key ​

Error Message / Symptom: Missing translation for key "unknown.key" in "en"

Cause: This message indicates that the specified translation key does not exist in the catalog for the provided locale.

Fix: Verify that the key exists in the translation catalog and is correctly structured. If needed, add the missing key with translations in your catalog.

typescript
const catalog = {
    greeting: { en: 'Hello', nl: 'Hallo' },
    // Ensure this key exists
    farewell: { en: 'Goodbye' },
};

const translator = new Translator({ catalog });
const farewell = translator.translate('farewell', 'en'); // Ensure this key exists in the catalog
console.log(farewell); // Output: Goodbye

Unsupported file extension ​

Error Message / Symptom: No files found matching provided paths. Make sure extensions are correct.

Cause: This error arises when the files being read do not match the expected extensions specified in the configuration.

Fix: Check the paths and file extensions provided to ensure that the configuration matches the actual files in your directories.

typescript
import { ContentFileSource } from 'blendsdk/i18n-node';

const source = new ContentFileSource({
    paths: ['./content'],
    extensions: ['.html', '.md'], // Check if files are actually in these formats
});

const catalog = await source.load(); // Ensure files match specified extensions
console.log(catalog);

Directory does not exist ​

Error Message / Symptom: Error: ENOENT: no such file or directory, stat 'path-to-directory'

Cause: Indicates that the specified directory does not exist or cannot be accessed.

Fix: Verify that the directory exists and that the path is correctly specified. Also, check for any file system permissions that may prevent access.

typescript
const source = new ContentFileSource({
    paths: ['./nonexistent-directory'], // Ensure the directory exists
});

const catalog = await source.load(); // Handle the case if the directory is invalid
console.log(catalog);

Debugging Strategies ​

  1. Logging: Add logging statements throughout your code to capture the flow of execution and the state of variables. This will help identify which part of the translation process is failing.

  2. Validate Input Data: Implement checks and validations on your translation data before loading them. Log any discrepancies or issues with the data format.

  3. Isolation Testing: Test components in isolation. For instance, if you are relying on a ContentFileSource, load just one file to ensure it can parse correctly before loading multiple files.

  4. Check File Paths: Utilize console.log() to log resolved file paths before attempting to read them. This can reveal issues with path definitions and ensure files are accessible.

typescript
try {
    const filePaths = await source.resolveAllPaths();
    console.log(filePaths);
} catch (error) {
    console.error(`Error resolving paths: ${error.message}`);
}
  1. Use Try/Catch Blocks: Wrap your asynchronous calls in try/catch blocks to catch any errors that might arise when loading translations or parsing data.

Known Pitfalls ​

  1. Assuming Single Locale: Developers often assume that their application will only need to support one locale. However, it’s critical to design your translation system from the beginning to handle multiple locales.

  2. Neglecting Pluralization: Failing to implement pluralization correctly can lead to awkward translations. Always test with different counts to ensure translations are appropriate for both singular and plural forms.

  3. Ignoring Localization Needs: Avoid using hardcoded strings in your application’s logic. Always utilize the translator for dynamic content to ensure comprehensive localization.

  4. Not Testing for Missing Keys: Failing to account for potential missing keys or to establish a fallback mechanism can lead to keys being displayed instead of translated text. Ensure that your onMissingTranslation callback is implemented appropriately.

  5. File Naming Convention: Ensure consistency in file naming when using the ContentFileSource. Files must follow the &lt;locale&gt;.&lt;key&gt;.&lt;ext&gt; format; doing otherwise will lead to parsing errors and missed translations.

  6. Async Behavior: Be cautious about the asynchronous nature of loading translations. Ensure your application handles translations after they have been fully loaded.

By following the troubleshooting guidelines and being mindful of common pitfalls, you will significantly reduce errors and improve the stability of your internationalization implementation with the blendsdk/i18n package.
