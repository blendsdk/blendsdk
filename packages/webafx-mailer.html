webafx-mailer Overview ​

What It Is ​

blendsdk/webafx-mailer is a robust email sending plugin for WebAFX that provides a unified interface for sending emails through both SMTP and in-memory backends. It allows applications to easily configure and utilize email functionalities with a focus on modularity, testing, and extensibility.

Key Features ​

  • Dual Email Backends: Supports both SMTP and Memory-based email sending.
  • Nodemailer Integration: Utilizes Nodemailer for reliable SMTP operations.
  • In-Memory Testing: The MemoryMailProvider allows for storing emails in-memory, making it ideal for unit testing.
  • WebAFX Plugin System: Integrates seamlessly with WebAFX as a singleton service with support for health checks and graceful shutdowns.
  • Flexible Configuration: Easily switch between backends depending on the environment (production or testing).

When To Use ​

  • When building a web application that requires email functionalities.
  • Ideal for applications needing to handle different environments with separate email configurations (e.g., testing with MemoryMailProvider).
  • Useful for applications where reliable email delivery is critical, leveraging SMTP.
  • When you require easy integration with the WebAFX framework and wish to benefit from its plugin system.

Architecture ​

The architecture of blendsdk/webafx-mailer is designed around the Provider pattern, with an abstract base class MailProvider from which specific implementations like SmtpMailProvider and MemoryMailProvider derive.

Key design patterns utilized:

  • Provider Pattern: Abstracts the email sending logic, allowing different backends to be interchangeable.
  • Factory Pattern: Factory methods (createMailPlugin(), smtpMailPlugin(), and memoryMailPlugin()) simplify provider instantiation and integration into WebAFX applications.

Dependencies ​

  • Peer Dependencies:

    • blendsdk/webafx: Required for plugin integration (optional).
    • typescript: Required to ensure smooth TypeScript compatibility.

  • Direct Dependencies:

    • nodemailer: Used for handling SMTP email sending operations.

Minimum Example ​

Here is a minimal example demonstrating the core functionality of the blendsdk/webafx-mailer package using the SMTP backend:

typescript
import { WebApplication } from "blendsdk/webafx";
import { smtpMailPlugin } from "blendsdk/webafx-mailer";

const app = new WebApplication();

app.use(smtpMailPlugin({
    host: "smtp.example.com",
    port: 587,
    secure: false,
    auth: {
        user: "user@example.com",
        pass: "secret",
    },
}));

// Sending an email
(async () => {
    const mailer = await app.services.get("mailer");
    const result = await mailer.send({
        from: "noreply@example.com",
        to: "recipient@example.com",
        subject: "Hello World",
        text: "This is a test email.",
    });
    console.log(result);
})();

webafx-mailer Core Concepts ​

MailProvider ​

What It Is ​

MailProvider is an abstract base class defining a uniform interface for all email providers, ensuring consistent behavior across different implementations such as SmtpMailProvider and MemoryMailProvider. It provides essential methods for sending emails, performing health checks, and gracefully shutting down.

How It Works ​

The MailProvider class outlines the necessary methods (send, health, and shutdown) that any mail provider class must implement. This abstraction allows developers to interact with different email backends (like SMTP and in-memory) without changing the client code. The class also facilitates the registration of the service name for integration into the WebAFX framework.

Complete Example ​

typescript
import { MailMessage, MailResult, SmtpMailProvider } from 'blendsdk/webafx-mailer';

const mailer: MailProvider = new SmtpMailProvider({ 
    host: "smtp.example.com", 
    port: 587, 
    secure: false, 
    auth: { user: "user@example.com", pass: "secret" } 
});

try {
    const result: MailResult = await mailer.send({ 
        from: "a@b.com", 
        to: "c@d.com", 
        subject: "Hi", 
        text: "Hello" 
    });
    console.log(result);
} catch (error) {
    console.error("Failed to send email:", error);
}

SmtpMailProvider ​

What It Is ​

SmtpMailProvider is a concrete implementation of the MailProvider class that utilizes Nodemailer to send emails through an SMTP server. It handles connection pooling and provides error handling for SMTP operations.

How It Works ​

The SmtpMailProvider wraps the Nodemailer transport, allowing it to send email messages. It uses methods like transporter.sendMail for sending messages and implements health checks using transporter.verify. The shutdown method closes the Nodemailer transport connection.

Complete Example ​

});

        subject: "Welcome", 
        text: "Thank you for signing up!"

    console.error("Error sending email:", error);

MemoryMailProvider ​

What It Is ​

MemoryMailProvider is a testing-focused implementation of the MailProvider that simulates email sending by storing messages in memory. It is ideal for unit tests where actual email delivery is not required.

How It Works ​

In the MemoryMailProvider, emails are stored in an internal array, allowing for verification of the sent content and assertions in tests. The provider includes methods to retrieve sent messages, clear the message store, and return the last sent message.

Complete Example ​

typescript
import { MemoryMailProvider, MailMessage, MailResult } from 'blendsdk/webafx-mailer';

const mailer: MemoryMailProvider = new MemoryMailProvider();

await mailer.send({ 
    from: "a@b.com", 
    to: "c@d.com", 
    subject: "Test", 
    text: "This is a test email." 
});

const sent = mailer.getSentMessages();
console.log(sent); // Check the stored message

webafx-mailer Advanced Patterns ​

Environment-Based Mail Provider Selection ​

When to Use ​

This pattern is useful when your application needs to dynamically select between an SMTP and a Memory mail provider based on the runtime environment (for example, running in a development environment versus production). This allows your application to use a memory provider during testing or development and an actual SMTP provider in production.

Complete Code Example ​

typescript
import { WebApplication } from "blendsdk/webafx";
import { createMailProvider, createMailPlugin } from "blendsdk/webafx-mailer";

const app = new WebApplication();

// Detect the environment and configure the mail provider accordingly
const providerConfig = {
    type: process.env.NODE_ENV === "production" ? "smtp" : "memory",
    host: process.env.SMTP_HOST,
    port: Number(process.env.SMTP_PORT || 587),
};

const mailProvider = createMailProvider(providerConfig);
app.use(createMailPlugin(mailProvider));

// Sending an email
(async () => {
    const mailer = await app.services.get(mailProvider.serviceName);
    try {
        const result = await mailer.send({
            from: "noreply@example.com",
            to: "recipient@example.com",
            subject: "Dynamic Mail Provider",
            text: "This message is sent based on the environment configuration.",
        });
        console.log(result);
    } catch (error) {
        console.error("Error sending email:", error);
    }
})();

Explanation ​

This pattern uses the createMailProvider factory function to instantiate the appropriate MailProvider based on the current environment. By checking process.env.NODE_ENV, the application can toggle between a SmtpMailProvider and a MemoryMailProvider, promoting modularity and ease of testing.

Caveats ​

  • Ensure that the environment variables SMTP_HOST and SMTP_PORT are set in production.
  • The application must be properly set up to load environment variables, e.g., using dotenv or similar.

When to Use ​

This pattern is beneficial when you want to configure your mail provider using a fluent interface that allows chaining of configuration options before creating the provider. This improves readability and makes the code cleaner.

Explanation ​

In this pattern, the SmtpMailProvider is initialized with basic settings. Assuming setTimeout is a custom method that allows you to modify the configuration in a fluent manner, this pattern improves the setup and makes it more elegant.

Caveats ​

  • Ensure that any additional methods, such as setTimeout, are implemented in the provider class. Fluent interfaces should be carefully designed to maintain method chaining.

Multi-Provider Registration in WebAFX ​

When to Use ​

Use this pattern when your application requires multiple distinct mail providers (e.g., different email types for marketing and transactional emails) to be registered within a single WebAFX application.

Complete Code Example ​

typescript
import { WebApplication } from "blendsdk/webafx";
import { createMailPlugin, smtpMailPlugin, memoryMailPlugin } from "blendsdk/webafx-mailer";

const app = new WebApplication();

const transactionalMailer = smtpMailPlugin({
    host: "smtp.transactional.com",
    port: 587,
    secure: true,
    auth: {
        user: "tx-user@example.com",
        pass: "tx-secret",
    },
});

const marketingMailer = memoryMailPlugin({
    serviceName: "marketing-mailer"
});

app.use(transactionalMailer);
app.use(marketingMailer);

// Sending a transactional email
(async () => {
    const txMailer = await app.services.get("mailer");
    try {
        const result = await txMailer.send({
            from: "tx@example.com",
            to: "recipient@example.com",
            subject: "Transactional Email",
            text: "This is a transactional email.",
        });
        console.log(result);
    } catch (error) {
        console.error("Transactional email failed:", error);
    }
})();

// Sending a marketing email
(async () => {
    const marketingMailer = await app.services.get("marketing-mailer");
    try {
        const result = await marketingMailer.send({
            from: "marketing@example.com",
            to: "recipient@example.com",
            subject: "Marketing Email",
            text: "This email promotes our new features.",
        });
        console.log(result);
    } catch (error) {
        console.error("Marketing email failed:", error);
    }
})();

Explanation ​

This pattern demonstrates how to register multiple mail providers with different configurations using the WebAFX plugin system. This provides the flexibility to handle various use cases (like transactional and marketing emails) under one roof efficiently.

Caveats ​

  • Each mail provider must have a unique service name to avoid conflicts when retrieving them from the service container.
  • Proper error handling should be implemented for both services, as they might fail independently.

Testing with In-Memory Mail Provider ​

When to Use ​

This pattern is particularly useful during unit testing where you want to simulate sending emails without hitting actual SMTP servers. It ensures that your tests remain fast and do not depend on any external resources.

Complete Code Example ​

typescript

const mailer = new MemoryMailProvider();

// Simulate sending emails in a test

    from: "test@example.com",
    to: "recipient@example.com",
    subject: "Test Email",
    text: "This message won't be sent, but stored in memory.",
});

expect(sentMessages[0].message.subject).toBe("Test Email");

Explanation ​

Using MemoryMailProvider allows you to verify that your email-sending logic works correctly without relying on an external system. After sending a message, you can easily retrieve and assert against the stored messages.

Caveats ​

  • Ensure that your tests account for the asynchronous nature of the send method and use the appropriate testing tools to handle promises.

webafx-mailer Best Practices ​

Do / Don't Pairs ​

1. Importing Packages ​

❌ Wrong:

typescript
const { smtpMailPlugin } = require('blendsdk/webafx-mailer');

✅ Correct:

typescript
import { smtpMailPlugin } from 'blendsdk/webafx-mailer';

Why: Always use ESM imports to ensure compatibility with TypeScript's strict mode and modern JavaScript practices.

2. Configuring Mail Provider with Incorrect Types ​

❌ Wrong:

typescript
const mailer = new SmtpMailProvider({ host: "smtp.example.com", port: "587" }); // Incorrect port type

✅ Correct:

typescript
const mailer = new SmtpMailProvider({ host: "smtp.example.com", port: 587 }); // Correct port type

Why: Ensuring the correct types is crucial for TypeScript's type safety, preventing runtime errors related to incorrect configurations.

3. Ignoring Async/Await for Sending Emails ​

❌ Wrong:

typescript
const result = mailer.send({ from: "a@b.com", to: "c@d.com", subject: "Hi", text: "Hello" });

✅ Correct:

typescript
try {
    const result = await mailer.send({ from: "a@b.com", to: "c@d.com", subject: "Hi", text: "Hello" });
} catch (error) {
    console.error("Error sending email:", error);
}

Why: Always use await for asynchronous calls to ensure that the operation completes before proceeding, and handle errors correctly with try/catch.

4. Not Validating Mail Message Structure ​

❌ Wrong:

typescript
const result = await mailer.send({ subject: "Hi" }); // Missing required fields

✅ Correct:

typescript
const result = await mailer.send({ from: "a@b.com", to: "c@d.com", subject: "Hi", text: "Hello" });

Why: Always provide all required fields in the mail message to prevent errors or unexpected behavior while sending emails.

5. Not Handling Shutdown Properly ​

❌ Wrong:

typescript
// Starting app without shutdown handling
app.use(smtpMailPlugin({ host: "smtp.example.com", port: 587 }));

✅ Correct:

typescript
app.use(createMailPlugin(mailer));

// On shutdown, gracefully shutdown the mailer
process.on("SIGINT", async () => {
    await mailer.shutdown();
    process.exit(0);
});

Why: Always implement graceful shutdown for resources to avoid memory leaks and ensure all messages are properly handled.

Anti-Patterns ​

1. Hardcoding Sensitive Information ​

Problem: Hardcoding SMTP credentials in your source code compromises security.

Example:

typescript
const mailer = new SmtpMailProvider({
    host: "smtp.example.com",
    port: 587,
    auth: { user: "user@example.com", pass: "password" }
});

Solution: Use environment variables to store sensitive data.

typescript
const mailer = new SmtpMailProvider({
    host: process.env.SMTP_HOST,
    port: Number(process.env.SMTP_PORT),
    auth: { user: process.env.SMTP_USER, pass: process.env.SMTP_PASS }
});

2. Overusing Memory Provider in Production ​

Problem: Relying solely on MemoryMailProvider for production, leading to lack of actual email delivery.

Example:

typescript
const mailer = new MemoryMailProvider(); // Used in production

Solution: Use MemoryMailProvider only for testing and development. Switch to SmtpMailProvider in production environments.

3. Ignoring Email Sending Errors ​

Problem: Not handling errors when sending emails can lead to silent failures.

Example:

typescript
await mailer.send({...}); // No error handling

Solution: Always implement error handling.

typescript
try {
    const result = await mailer.send({...});
} catch (error) {
    console.error("Failed to send email:", error);
}

Performance Tips ​

  1. Batching Emails: If you need to send a large number of emails, consider batching them to reduce network overhead.

  2. Pooling Connections: Use the built-in connection pooling feature of nodemailer effectively to manage connections efficiently.

  3. Logging and Monitoring: Implement logging for email sending to help identify issues in performance and delivery. Tools like Sentry or similar can provide insights into errors.

Security Considerations ​

  • Always Use Environment Variables: Store sensitive information like SMTP credentials in environment variables instead of hardcoding them.

  • Validate Input: Always validate email addresses and message contents to prevent injections and spam. Ensure that user inputs are sanitized before sending.

  • Use Secure Connections: Ensure that the secure option is set to true for production SMTP configurations to protect sensitive information during transmission.

  • Rate Limiting: Implement rate limiting to prevent abuse of the email sending functionality and avoid getting blacklisted by email services.

webafx-mailer Troubleshooting ​

Common Errors ​

1. "Error: connect ECONNREFUSED [::1]:... or [127.0.0.1]:..." ​

  • Cause: The SMTP server is not running, or the connection details (host, port) are incorrect.

  • Fix: Ensure that your SMTP server (e.g., Mailpit) is running and configured correctly.

    typescript
    const mailer = new SmtpMailProvider({
    host: "localhost", // Ensure this is correct
    port: 1025,       // Check that Mailpit is using this port
    secure: false,
    auth: {
        user: "user",
        pass: "password",
    },
});

2. "Error: SMTP authentication failed" ​

  • Cause: Incorrect SMTP credentials (user or password) provided.

  • Fix: Verify your SMTP authentication credentials.

    typescript
    // Double-check the user and password
const mailer = new SmtpMailProvider({
    host: "smtp.example.com",
    port: 587,
    secure: false,
    auth: {
        user: "correct_user@example.com",
        pass: "correct_password",
    },
});

3. "Error: Invalid email address" ​

  • Cause: The provided email address format is invalid.

  • Fix: Ensure all email addresses in the from, to, cc, and bcc fields are correctly formatted.

    typescript
    const result = await mailer.send({
    from: "sender@example.com", // Ensure format is valid
    to: "recipient@example.com", // Ensure format is valid
    subject: "Hi",
    text: "Hello!",
});

4. "Error: Cannot send new mail, provider is shut down" ​

  • Cause: The SMTP provider has been shut down and cannot process new requests.

  • Fix: Ensure the provider is running before sending emails.

    typescript
    // Check if mailer is shut down
if (!mailer.shutdown) {
    throw new Error("Mailer is shut down; cannot send emails.");
}
const result = await mailer.send({...});

5. "Error: Invalid 'from' address" ​

  • Cause: The 'from' email address is either missing or invalid.

  • Fix: Ensure that the 'from' field is populated and properly formatted.

    typescript
    const result = await mailer.send({
    from: "valid.sender@example.com", // Must be valid
    to: "recipient@example.com",
    subject: "Subject",
    text: "Email body",
});

Debugging Strategies ​

  1. Check Logs: Always check your server logs or console outputs for detailed error messages.

  2. Verify SMTP Server Connectivity: Use tools like telnet or nc to ensure your application can reach the SMTP server on the designated port.

    bash
    telnet localhost 587

  3. Inspect Email Formatting: Review the email structure you are trying to send; ensure all required fields (from, to, subject, text) are being populated correctly.

  4. Run Tests: Ensure your memory-based tests are passing before testing with an SMTP provider. Use the MemoryMailProvider to mock email sending in unit tests without external dependencies.

  5. Simulate Failures: If you suspect the health check is not functioning correctly, simulate failures by temporarily invalidating SMTP credentials or shutting down the SMTP server.

  6. Error Handling: Implement comprehensive try/catch blocks around your send methods to capture and log exceptions.

    typescript
    try {
    const result = await mailer.send(...);
} catch (error) {
    console.error('Error while sending email:', error);
}

Known Pitfalls ​

  • Ignoring Asynchronous Operations: Ensure that all email sending operations are awaited to prevent premature script termination. Always use await when calling asynchronous methods.

  • Overriding Transports Without Close: If switching between email transports (e.g., from SMTP to MemoryMailProvider), ensure active transports are properly closed to avoid leaks or conflicts.

  • Confusing Memory and SMTP Providers: When running tests, ensure you are using the MemoryMailProvider for simulations without sending actual emails to maintain test isolation.

  • Environment Variables Misconfiguration: Double-check that all SMTP configuration parameters are correctly set in your environment, especially during deployment.

  • Not Validating Email Addresses: Always validate email addresses before attempting to send to avoid runtime errors. Use regex or libraries to ensure correctness.

  • Using Hardcoded Credentials: Avoid hardcoding sensitive information like SMTP credentials in your source code. Use environment variables or secure vaults instead.
