webafx-auth Overview ​

What It Is ​

blendsdk/webafx-auth is a comprehensive token validation and authentication plugin for WebAFX, designed to support a variety of authentication mechanisms including JWT, OAuth2 introspection, OpenID Connect (OIDC), and multi-tenant providers.

Key Features ​

  • Multiple Authentication Providers: Supports various authentication methods including:
    • JwtAuthProvider
    • IntrospectionAuthProvider
    • OidcAuthProvider
    • TenantAuthProvider
    • MemoryAuthProvider
  • Token Extraction Flexibility: Configurable token extraction strategies from headers, cookies, or query parameters.
  • Claims Mapping: Customizable mapping of token claims to standardized AuthResult formats.
  • Easy Integration: Create authentication plugins for use with WebAFX applications.
  • Asynchronous Operations: Uses async/await for handling token validation and authentication lifecycles.

When To Use ​

  • Web applications requiring secure authentication via JWT, OAuth2, or OpenID Connect.
  • Multi-tenant systems where different configurations are needed for user authentication.
  • Applications that require a simple way to validate tokens and manage user sessions.
  • Test environments that demand controlled authentication without external dependencies (using MemoryAuthProvider).

Architecture ​

The blendsdk/webafx-auth package is designed based on several key design patterns:

  • Abstract Factory Pattern: The AuthProvider serves as a base class for various authentication implementations, with each concrete implementation handling a specific type of authentication.
  • Chain of Responsibility Pattern: Configurable token extraction strategies allow the system to attempt multiple sources (header, cookie, query) in order until it successfully retrieves a token.
  • Strategy Pattern: Supports various claims mapping strategies, allowing developers to define how claims from tokens are transformed into the standardized AuthResult.

Dependencies ​

Peer Dependencies ​

  • blendsdk/webafx: ^5.42.0 (optional)
  • typescript: ^5.6.0

Core Dependencies ​

  • jose: ^6.2.2 (for JWT verification)
  • openid-client: ^6.3.1 (for OIDC flows)

Minimum Example ​

Here’s a brief example demonstrating the usage of JwtAuthProvider to validate a JWT token:

typescript
import { JwtAuthProvider, AuthResult } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();
const provider = new JwtAuthProvider({
    secret: 'my-256-bit-secret',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',
});

app.use(async (req, res, next) => {
    try {
        // Extract the token
        const token = req.headers['authorization']?.split(' ')[1];
        const authResult: AuthResult | undefined = token ? await provider.validate(token) : undefined;
        req.user = authResult;
    } catch (error) {
        console.error('Authentication Error:', error);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
});

app.get('/protected', (req, res) => {
    if (!req.user) return res.status(401).send('Unauthorized');
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

webafx-auth Core Concepts ​

AuthProvider ​

What It Is ​

The AuthProvider is an abstract base class that provides the foundational structure for all authentication providers in the blendsdk/webafx-auth package. This class encapsulates the common authentication lifecycle, including token extraction, validation, and claims mapping.

How It Works ​

AuthProvider defines a configurable token extraction chain and provides a standard authenticate() method to extract a token from requests, validate it, and return the authenticated identity (in the form of an AuthResult). Implementing providers must only implement the validate() method, while common functionalities such as token extraction and claims mapping are inherited from this base class.

Complete Example ​

typescript
import { AuthProvider, AuthResult, AuthProviderConfig } from 'blendsdk/webafx-auth';
import type { Request } from 'express';

export abstract class CustomAuthProvider extends AuthProvider {
    constructor(config: AuthProviderConfig) {
        super(config);
    }

    async validate(token: string): Promise<AuthResult | undefined> {
        // Custom validation logic
    }
}

// Example usage in your application:
const provider = new CustomAuthProvider({ serviceName: 'customAuth' });
const req: Request = /* obtain express request object */;
const result = await provider.authenticate(req);

JwtAuthProvider ​

What It Is ​

JwtAuthProvider is a concrete implementation of AuthProvider that validates JSON Web Tokens (JWTs) locally. It supports HMAC and RSA/EC algorithms and provides synchronous validation without requiring a network call.

How It Works ​

This provider utilizes the jose library to verify JWT signatures and validate claims such as exp, nbf, iss, and aud. The provider can be configured with a signing secret, expected algorithms, and optional issuer and audience validations. Each JWT that is validated results in an AuthResult object containing user information.

Complete Example ​

typescript
import { JwtAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();
const provider = new JwtAuthProvider({
    secret: 'my-256-bit-secret',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',
});

app.use(async (req, res, next) => {
    try {
        const token = req.headers['authorization']?.split(' ')[1];
        const authResult = token ? await provider.authenticate(req) : undefined;
        req.user = authResult; // Attach user data to the request
    } catch (error) {
        console.error('Authentication Error:', error);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
});

app.get('/protected', (req, res) => {
    if (!req.user) return res.status(401).send('Unauthorized');
    res.send(`Hello ${req.user.sub}`);

OidcAuthProvider ​

What It Is ​

OidcAuthProvider is a specialized implementation of AuthProvider that supports OpenID Connect (OIDC) authentication. It allows for validation of access tokens based on OIDC discovery mechanisms and provides methods for managing the authorization code flow with PKCE.

How It Works ​

This provider performs OIDC discovery to retrieve public keys for validating JWT access tokens via jose. It enables session management through BFF (Backend for Frontend) patterns, allowing clients to obtain user information seamlessly. The provider can operate in both static single-tenant and dynamic multi-tenant configurations.

Complete Example ​

typescript
import { OidcAuthProvider } from 'blendsdk/webafx-auth';

const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'my-app',
    clientSecret: 'secret',
    redirectUri: 'https://app.example.com/callback',
});

async function handleLogin(code: string) {
    const tokens = await provider.exchangeCode({
        codeVerifier: 'verifier',  // Code received from OIDC
        callbackUrl: 'https://app.example.com/callback?code=' + code,
    });

    const userInfo = await provider.fetchUserInfo(tokens.accessToken);
    console.log(userInfo);
}

MemoryAuthProvider ​

What It Is ​

MemoryAuthProvider is a mock implementation of AuthProvider designed for use in testing and development environments. It validates tokens against a pre-defined map of valid tokens to their corresponding AuthResult objects.

How It Works ​

This provider allows dynamic management of tokens with methods to add or remove tokens at runtime. It serves as a useful tool for creating automated tests or simulating various authentication scenarios without relying on external services.

Complete Example ​

typescript
import { MemoryAuthProvider } from 'blendsdk/webafx-auth';

const provider = new MemoryAuthProvider({
    validTokens: {
        'test-token': { sub: 'user-1', claims: { role: 'user' }, token: 'test-token' },
    },
});

async function authenticateRequest(req) {
    const res = await provider.authenticate(req);
    return res;
}

webafx-auth Advanced Patterns ​

Using Multiple Providers for Enhanced Security ​

When to Use ​

This pattern is useful when your application requires a layered approach to authentication, such as combining JWT validation with OIDC for enhanced security and flexibility.

Complete Example ​

typescript
import express from 'express';
import { JwtAuthProvider, OidcAuthProvider } from 'blendsdk/webafx-auth';

// Express app setup
const app = express();

// JWT Provider - for API token validation
const jwtProvider = new JwtAuthProvider({
    secret: 'my-256-bit-secret',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',
});

// OIDC Provider - for user authentication
const oidcProvider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'oidc-client-id',
    clientSecret: 'oidc-client-secret',
    redirectUri: 'https://yourapp.com/callback',
});

// Middleware - authenticate JWT token first
app.use(async (req, res, next) => {
    try {
        const token = req.headers['authorization']?.split(' ')[1];
        const jwtResult = token ? await jwtProvider.authenticate(req) : undefined;
        
        if (!jwtResult) {
            // Fallback to OIDC if JWT token is not valid
            const oidcResult = await oidcProvider.authenticate(req);
            req.user = oidcResult;
        } else {
            req.user = jwtResult;
        }
    } catch (error) {
        console.error('Authentication Error:', error);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
});

// Example protected route
app.get('/protected', (req, res) => {
    if (!req.user) return res.status(401).send('Unauthorized');
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

Why This Pattern Is Valuable ​

  • Enhanced Security: By using multiple providers, you can employ different authentication mechanisms (like JWT for API calls and OIDC for user sessions) tailored to various parts of your application.
  • Fallback Mechanism: Ensures that if one authentication method fails, another can still attempt to authenticate the user, providing a seamless experience.

Caveats ​

  • Performance: Multiple authentication checks might incur additional overhead; assess performance impacts based on your application's specific needs.
  • Complexity: Introducing multiple providers can complicate the authentication flow; careful design and documentation are essential.

Dynamic Multi-Tenant OIDC Configuration ​

When to Use ​

Use this pattern when your application serves multiple tenants, each requiring separate authentication configurations against the same authentication server.

Complete Example ​

typescript
import express from 'express';
import { OidcAuthProvider } from 'blendsdk/webafx-auth';

const app = express();

const provider = new OidcAuthProvider({
    serviceName: 'multi-tenant-oidc',
    configFactory: async (req) => {
        const tenantId = req.headers['x-tenant-id']; // Extract tenant ID from request headers

        // Dynamically resolve OIDC config based on the tenant
        return {
            issuerUrl: `https://${tenantId}.auth.example.com`,
            clientId: `${tenantId}-client`,
            clientSecret: `${tenantId}-secret`,
            redirectUri: `https://${tenantId}.example.com/callback`,
        };
    },
});

// Middleware - use OIDC Provider for authentication
app.use(async (req, res, next) => {
    try {
        const result = await provider.authenticate(req);
        if (!result) return res.status(401).send('Unauthorized');
        req.user = result;
    } catch (error) {
        console.error('Authentication Error:', error);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
});

// Example protected route
app.get('/protected', (req, res) => {
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

Why This Pattern Is Valuable ​

  • Tenant-Specific Configurations: Each tenant can use different configurations based on their needs, making it highly customizable.
  • Single Codebase: Maintains a single implementation of the authentication mechanism while allowing multi-tenancy, keeping development streamlined.

Caveats ​

  • Discovery Overhead: Each request may trigger a discovery call if not properly cached, potentially impacting performance.
  • Complex Configuration: Ensure that the configurations and retrieval mechanisms are thoroughly tested to prevent configuration errors.

Combining MemoryAuthProvider for Testing with Production Flow ​

When to Use ​

This pattern is ideal for testing the entire authentication system with real HTTP requests without requiring real tokens or network calls, ensuring smooth transitions between test and production environments.

Complete Example ​

typescript
import express from 'express';
import { MemoryAuthProvider, JwtAuthProvider } from 'blendsdk/webafx-auth';

// Express app setup
const app = express();

// Memory Auth Provider for testing
const memoryProvider = new MemoryAuthProvider({
    validTokens: {
        'test-token': { sub: 'test-user', claims: {}, token: 'test-token' },
    },
});

// JWT Provider for production
const jwtProvider = new JwtAuthProvider({
    secret: 'my-256-bit-secret',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',
});

// Middleware - switch based on environment
app.use(async (req, res, next) => {
    try {
        let authResult;
        if (process.env.NODE_ENV === 'test') {
            // Use Memory Provider in tests
            authResult = await memoryProvider.authenticate(req);
        } else {
            // Use JWT Provider in production
            const token = req.headers['authorization']?.split(' ')[1];
            authResult = token ? await jwtProvider.authenticate(req) : undefined;
        }

        if (!authResult) return res.status(401).send('Unauthorized');
        req.user = authResult;
    } catch (error) {
        console.error('Authentication Error:', error);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    next();
});

// Example protected route
app.get('/protected', (req, res) => {
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

Why This Pattern Is Valuable ​

  • Simplified Testing: Quickly switch authentication methods for testing versus production without altering application routes or flow.
  • Consistency: Maintains consistent interfaces and patterns across different environments, making it easier to develop and debug.

Caveats ​

  • Environment Configuration: Ensure that environment variables are configured correctly to prevent unintended behavior in production.
  • Token Management: A well-configured memory provider can help manage token validity during tests but can lead to oversight if not reset properly between tests.

webafx-auth Best Practices ​

Do / Don't Pairs ​

Do Properly Handle Token Validation ​

❌ Wrong: Failing to validate the token

typescript
import { JwtAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();
const provider = new JwtAuthProvider({ secret: 'my-secret' });

app.use(async (req, res, next) => {
    const token = req.headers['authorization']?.split(' ')[1];
    if (!token) {
        return res.status(401).send('Unauthorized');
    }
    const result = await provider.validate(token); // This might return undefined
    req.user = result; // result could be undefined
    next();
});

✅ Correct: Validate the token and handle errors

typescript
import { JwtAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();
const provider = new JwtAuthProvider({ secret: 'my-secret' });

app.use(async (req, res, next) => {
    try {
        const token = req.headers['authorization']?.split(' ')[1];
        if (!token) return res.status(401).send('Unauthorized');

        const result = await provider.validate(token);
        if (!result) return res.status(401).send('Unauthorized'); // Handle invalid token

        req.user = result; // Valid user result
        next();
    } catch (error) {
        console.error('Authentication Error:', error); // Log unexpected errors
        return res.status(500).send('Internal Server Error');
    }
});

Do Use the Appropriate Provider for the Use Case ​

❌ Wrong: Using MemoryAuthProvider in production

typescript
import { MemoryAuthProvider } from 'blendsdk/webafx-auth';

const provider = new MemoryAuthProvider({
    validTokens: {
        'user-token': { sub: 'user-1', claims: {}, token: 'user-token' },
    },
});

// In production, you'd incorrectly use a MemoryAuthProvider instead of JwtAuthProvider or OidcAuthProvider.

✅ Correct: Choose the right provider based on the context

typescript
import { JwtAuthProvider, OidcAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();

// Choose provider based on application requirements
const isProduction = process.env.NODE_ENV === 'production';
const provider = isProduction 
    ? new JwtAuthProvider({ secret: 'my-secret', algorithms: ['HS256'] }) 
    : new MemoryAuthProvider({
        validTokens: {
            'test-token': { sub: 'test-user', claims: {}, token: 'test-token' },
        },
    });

Do Implement Session Management Efficiently ​

❌ Wrong: Not handling sessions and tokens properly

typescript
import { OidcAuthProvider } from 'blendsdk/webafx-auth';

const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://app.example.com/callback',

// Failing to store, retrieve, and clear session states can lead to unauthorized access

✅ Correct: Properly handle session state

typescript
import { OidcAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

const app = express();
const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://app.example.com/callback',
});

app.use(async (req, res, next) => {
    const tokens = await provider.exchangeCode({
        codeVerifier: 'verifier',
        callbackUrl: 'https://app.example.com/callback?code=auth-code',

    // Store session details securely (e.g. as a signed cookie)
    await provider.storeSession(req, res, {
        accessToken: tokens.accessToken,
        refreshToken: tokens.refreshToken,

Anti-Patterns ​

Using any Type for Token Claims ​

Do not use any type when defining token claims—it loses the benefits of TypeScript’s type safety.

Bad Example:

typescript
const claims: any = {}; // Avoid using any

const authResult: AuthResult = { sub: claims.sub };

Good Example:

typescript
import type { AuthResult } from 'blendsdk/webafx-auth';

const claims: Record<string, unknown> = {}; // Use specific types or shapes

const authResult: AuthResult = { 
    sub: claims.sub as string, // Ensure sub is a string 
    claims 
};

Ignoring Errors from Provider Methods ​

Ignoring errors from methods can lead to silent failures.

Bad Example:

typescript
const result = await provider.validate(token); // Not checking for undefined

Good Example:

typescript
try {
    const result = await provider.validate(token);
    if (!result) throw new Error('Invalid token');
} catch (error) {
    console.error(error); // Log or handle unexpected issues
}

Performance Tips ​

Optimize Token Validations ​

Use caching strategies to avoid frequent rediscovery of OIDC configurations. Ensure that the discovery information is retrieved once and stored for reuse within the TTL.

Bad Example:

typescript
async authenticate(req) {
    // Discovery for each request can be performance-heavy
    const discovery = await client.discovery(issuerUrl, clientId);
    const result = await provider.validate(token);
}

Good Example:

typescript
let cachedDiscovery: client.Configuration | null = null;

async authenticate(req) {
    if (!cachedDiscovery) {
        cachedDiscovery = await client.discovery(issuerUrl, clientId);
    }
    const result = await provider.validate(token);
}

Security Considerations ​

Use Secure Cookies and Headers ​

When using cookies to manage sessions or tokens, always ensure they are set with secure and HTTP-only flags to prevent cross-site scripting (XSS) attacks. Additionally, validate the source of the request to protect against CSRF.

Bad Example:

typescript
res.cookie('session_id', sessionId); // Missing security settings

Good Example:

typescript
res.cookie('session_id', sessionId, {
    secure: true, // Only send on HTTPS
    httpOnly: true, // Prevent access to cookie via JavaScript
    sameSite: 'lax' // Provide CSRF protection
});

Validate All External Inputs ​

Ensure that all incoming data, especially from query parameters and body requests from users, is validated and sanitized to prevent injection attacks.

Bad Example:

typescript
const token = req.query.token; // No validation

Good Example:

typescript
const token = String(req.query.token).trim(); // Sanitization/validation

    secret: 'my-secret-key',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',

webafx-auth Troubleshooting ​

Common Errors ​

JWT Token Validation Errors ​

Error Message / Symptom: Error: invalid signature

Cause: The token signature does not match the expected signature based on the provided secret or public key. This usually occurs when the token is corrupted, expired, or has been signed with a different key.

Fix: Confirm that the token was signed with the correct key and that you are using the matching secret in your JwtAuthProvider.

typescript
import { JwtAuthProvider } from 'blendsdk/webafx-auth';

const provider = new JwtAuthProvider({
    secret: 'my-256-bit-secret',
    algorithms: ['HS256'],
});

try {
    const result = await provider.validate(token);
} catch (error) {
    console.error('Token validation error:', error.message);
}

Error Message / Symptom: Token has expired

Cause: The token's exp (expiration) claim has reached or surpassed the current time.

Fix: Make sure to implement a token refresh mechanism. Also, confirm that the token is valid upon creation and monitor the expiration time.

typescript
// Example of token creation with proper expiration setting
import { SignJWT } from 'jose';

const token = await new SignJWT({ sub: 'user-1' })
    .setIssuedAt()
    .setExpirationTime('2h') // Expires in 2 hours
    .setProtectedHeader({ alg: 'HS256' })
    .sign(new TextEncoder().encode('my-256-bit-secret'));

Error Message / Symptom: No matching key: { "alg": "RS256" }

Cause: The provider was configured to use an asymmetric key (like RSA) but received a token that was signed with a different key.

Fix: Ensure that the correct keys are configured and available to your application for validation.

typescript
const provider = new JwtAuthProvider({
    secret: rsaPublicKey, // Ensure this is a CryptoKey object
    algorithms: ['RS256'],
});

OIDC Authentication Errors ​

Error Message / Symptom: Missing state or code parameter in the callback

Cause: The OIDC callback URL does not contain the required parameters that are essential for validating the request.

Fix: Ensure that your application correctly handles the redirect and that the parameters are included:

typescript
const callbackUrl = await provider.buildAuthorizationUrl();
// Ensure that the callback URL and its parameters are correctly logged
console.log('Redirecting to:', callbackUrl);

Error Message / Symptom: Error fetching user info: 401 Unauthorized

Cause: The access token provided is either invalid or expired.

Fix: Ensure that prior to calling fetchUserInfo, the access token is valid, and implement a mechanism to refresh tokens when they expire.

typescript
async function handleUserInfo(accessToken: string) {
    try {
        const userInfo = await provider.fetchUserInfo(accessToken);
        console.log('User Info:', userInfo);
    } catch (error) {
        console.error('Error fetching user info:', error.message);
    }
}

Memory Provider Errors ​

Error Message / Symptom: Token not found

Cause: The requested token does not match any valid tokens stored in the MemoryAuthProvider.

Fix: Make sure the token is correctly registered in the validTokens map when instancing MemoryAuthProvider.

typescript
const provider = new MemoryAuthProvider({
    validTokens: {
        'valid-token': { sub: 'user-1', claims: {}, token: 'valid-token' },
    },
});

Debugging Strategies ​

  1. Logging: Add extensive logging for every step of the authentication process. This includes when tokens are created, validated, and errors encountered.

  2. Error Handling: Wrap authentication logic in try/catch blocks. Ensure you handle different types of errors (e.g., validation, expired tokens) explicitly.

  3. Unit Testing: Implement comprehensive unit tests to cover various error scenarios. Use testing libraries like Vitest to simulate failures and validate error handling.

  4. Isolation of Failures: When encountering issues, isolate the components involved (e.g., the provider, request handling) to see where errors are occurring.

Known Pitfalls ​

  • Ignoring Expiration: Always check and handle token expiration issues. Never assume a token is valid unless it has been freshly validated.

  • Not Testing Configurations: Always thoroughly test different configurations, including multi-tenant settings, to ensure that each provider behaves as expected in all scenarios.

  • Failing to Secure Cookies: Always ensure security settings for cookies used in session management are correctly specified (e.g., httpOnly, secure).

  • Poor Error Messaging: Ensure your application provides clear and actionable error messages to help diagnose issues more effectively during authentication.

By following these guidelines and understanding potential issues, you can streamline the troubleshooting process for blendsdk/webafx-auth and provide a more robust authentication experience in your applications.

This example illustrates how to handle session storing securely after user authentication using OidcAuthProvider.

typescript
import express from 'express';
import { OidcAuthProvider } from 'blendsdk/webafx-auth';

const app = express();
const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
});

app.get('/callback', async (req, res) => {
    const tokens = await provider.exchangeCode({
        codeVerifier: 'verifier-123',
        callbackUrl: 'https://yourapp.com/callback?code=' + req.query.code,
    });
    
    // Store session cookies securely
    res.cookie('session_id', tokens.accessToken, {
        httpOnly: true,
        secure: true,
    });
    res.send('Logged in successfully');
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});
