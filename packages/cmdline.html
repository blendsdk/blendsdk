# cmdline Overview

---

## What It Is

`blendsdk/cmdline` is a TypeScript library designed for parsing command-line arguments and interpreting options for web applications. It provides developers with a straightforward way to set up command-line interfaces, allowing them to manage user inputs effectively.

---

## Key Features

- **Command Parsing**: Easily define and parse commands with their options.
- **Validation**: Built-in validation for option types, including strings, numbers, booleans, and custom validators.
- **Help System**: Automatic generation of help messages based on command definitions and options.
- **Multi-Value Support**: Handle options that can accept multiple values seamlessly.
- **Custom Error Handling**: Define and manage custom error handlers for improved user feedback.
- **Flexible Configuration**: Allow for customization of global options and command-specific settings.
- **Opt-in Strict Parsing**: Set `strict: true` to reject unknown or invalid input before a command
  handler runs. Strict failures reject with `CommandLineValidationError`; legacy mode remains the
  v5 default.

---

## When To Use

Consider using `blendsdk/cmdline` in the following scenarios:

- Developing command-line tools that require input from users.
- Building applications where command-line arguments dictate behavior or configuration.
- Creating scripts where automated input management and error handling enhance usability.
- Implementing features that require validation of complex argument structures efficiently.

---

## Architecture

The architecture of `blendsdk/cmdline` is centered around the **Command Line Parser** pattern, supporting a modular approach in handling multiple commands and options. Key design patterns used include:

- **Builder Pattern**: For constructing command configurations.
- **Strategy Pattern**: Options can have different validation strategies through customizable validators.

This structure promotes extensibility and maintainability, enabling developers to add new commands and functionalities without significant changes to existing code.

---

## Dependencies

- **Peer Dependencies**:
  - `typescript`: Required for TypeScript features and type checking.

- **Dependencies**:
  - `blendsdk/stdlib`: Provides utility functions to enhance validation and type checking.

---

## Minimum Example

Here is a minimal example demonstrating the core functionality of the `blendsdk/cmdline` package:

```typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'example-cli' });

parser.addCommand({
  name: 'greet',
  options: [
    {
      name: 'name',
      type: 'string',
      required: true,
      description: 'Name of the person to greet',
    },
  ],
  handler: async options => {
    console.log(`Hello, ${options.name}!`);
  },
});

await parser.execute();
```

This example sets up a simple command-line interface for a greeting command, taking a required name option, and outputs a greeting message based on the input.

# cmdline Core Concepts

---

## CommandLineParser

### What It Is

`CommandLineParser` is the core class of the `blendsdk/cmdline` library, designed to parse command-line arguments and manage commands and their options effectively. It handles the configuration, execution, and validation of commands specified via command-line input.

### How It Works

The `CommandLineParser` works by reading the command-line arguments from `process.argv`. It tokenizes the input to separate commands from options and their values. The class maintains a list of commands, validates options against their defined types and constraints, and executes the appropriate command with the provided options, invoking their associated handlers.

### Complete Example

```typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'example-cli' });

parser.addCommand({
  name: 'greet',
  description: 'Greets the user',
  options: [
    {
      name: 'name',
      type: 'string',
      required: true,
      description: 'Name of the person to greet',
    },
  ],
  handler: async options => {
    console.log(`Hello, ${options.name}!`);
  },
});

await parser.execute();
```

ICommand Interface ​

What It Is ​

The ICommand interface defines the structure of a command that can be added to the CommandLineParser. It specifies the properties that describe the command's name, options, descriptions, and execution behavior.

How It Works ​

Commands are defined using the ICommand interface, allowing developers to specify essential details such as the command name, a description, its associated options, and a handler function that executes when the command is called.

Complete Example ​

typescript
import { CommandLineParser, ICommand } from 'blendsdk/cmdline';

const myCommand: ICommand = {
  name: 'say',
  description: 'Outputs a message to the console',
  options: [
    {
      name: 'message',
      type: 'string',
      required: true,
      description: 'The message to be output',
    },
  ],
  handler: async options => {
    console.log(options.message);
  },
};

const parser = new CommandLineParser({ name: 'example-cli' });
parser.addCommand(myCommand);

await parser.execute();

ICommandOption Interface ​

What It Is ​

The ICommandOption interface defines the structure of options that can be associated with commands in the CommandLineParser. It includes specifications for the option name, type, default values, and validation rules.

How It Works ​

Each command can have multiple options defined using the ICommandOption interface. This interface allows developers to specify how each option behaves, including its type, whether it is required, and any default values or custom validation functions.

Complete Example ​

typescript
import { CommandLineParser, ICommand, ICommandOption } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'example-cli' });

const command: ICommand = {
  name: 'config',
  description: 'Configure options',
  options: [
    {
      name: 'verbose',
      short: 'v',
      type: 'boolean',
      description: 'Enable verbose output',
      default: false,
    },
    {
      name: 'timeout',
      type: 'number',
      description: 'Specify a timeout value',
      required: true,
    },
  ],
  handler: async options => {
    console.log(`Verbose: ${options.verbose}, Timeout: ${options.timeout}`);
  },
};

parser.addCommand(command);
await parser.execute();

Tokenization of Arguments (IToken) ​

What It Is ​

The IToken interface represents each parsed token from the command-line arguments, providing a structured way to understand and analyze the input provided to the command-line parser.

How It Works ​

As command-line arguments are parsed, each token is created and classified according to its type (command, option, value). The tokens are later validated and used to execute the appropriate command's handler with the respective options.

Complete Example ​

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'example-cli' });

parser.addCommand({
  name: 'process',
  options: [
    {
      name: 'file',
      type: 'string',
      required: true,
    },
  ],
  handler: async options => {
    console.log(`Processing file: ${options.file}`);
  },
});

await parser.execute();

Error Handling ​

What It Is ​

Strict mode collects parser-owned failures into CommandLineValidationError. Its ordered issues array retains specific errors such as MissingRequiredOptionError, UnknownCommandError, and MalformedArgumentError. The command handler never runs after one of these failures.

How It Works ​

errorHandler is an awaited presentation hook. When configured, it replaces built-in invalid-input output, but execute() still rejects so the caller can choose its exit policy. Clean automatic help resolves without invoking the command handler. Similarity text such as Did you mean [--output]? is diagnostic only and never corrects the input.

Complete Example ​

typescript
import { CommandLineParser, CommandLineValidationError } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'example-cli', strict: true });

parser.addCommand({
  name: 'upload',
  options: [
    {
      name: 'file',
      type: 'string',
      required: true,
    },
  ],
  handler: async options => {
    console.log(`Uploading file: ${options.file}`);
  },
});

try {
  await parser.execute();
} catch (error) {
  if (error instanceof CommandLineValidationError) {
    for (const issue of error.issues) console.error(issue.message);
    process.exitCode = 1;
  } else {
    throw error;
  }
}

## Installation

To install the `blendsdk/cmdline` package, use npm or yarn:

```bash
npm install blendsdk/cmdline
```

or

bash
yarn add blendsdk/cmdline

Quick Start ​

Here's a minimal setup to get you started with the blendsdk/cmdline package. This example creates a command-line parser that greets the user.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'greeter' });

parser.addCommand({
  name: 'greet',
  options: [
    {
      name: 'name',
      type: 'string',
      required: true,
      description: 'Name of the person to greet',
    },
  ],
  handler: async options => {
    console.log(`Hello, ${options.name}!`);
  },
});

await parser.execute();

Fundamentals ​

1. CommandLineParser ​

The CommandLineParser is the core class for parsing command-line arguments.

Example: Basic Instance Creation

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'my-cli' });

2. Adding a Command ​

You can add commands to the parser with their associated options and handlers.

Example: Adding a Command

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'calculator' });

parser.addCommand({
  name: 'add',
  options: [
    {
      name: 'a',
      type: 'number',
      required: true,
    },
    {
      name: 'b',
      type: 'number',
      required: true,
    },
  ],
  handler: async options => {
    const sum = options.a + options.b;
    console.log(`The sum is: ${sum}`);
  },
});

3. Executing a Command ​

To run the command-line parser and execute the appropriate command, use the execute method.

Example: Executing the Parser

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'calculator' });

// Add commands here...

await parser.execute();

Configuration ​

The CommandLineParser supports various configuration options, allowing you to customize its behavior. Below are common configuration options.

NameTypeDefaultDescription
namestringRequiredName of the application/script.
versionstring1.0Version of the application.
strictbooleanfalseReject unknown and invalid input before handler execution.
skipHelpbooleanfalseSkip automatic help option addition.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({
  name: 'my-app',
  version: '2.0.0',
  skipHelp: true,
});

Error Handling ​

Handling errors gracefully is essential in any command-line application. The blendsdk/cmdline package provides several error classes to help identify and manage errors.

Example: Handling Errors

typescript
import { CommandLineParser, CommandLineValidationError } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'error-handler', strict: true });

parser.addCommand({
  name: 'config',
  options: [
    {
      name: 'option1',
      type: 'string',
      required: true,
    },
  ],
  handler: async options => {
    console.log(`Option 1 value: ${options.option1}`);
  },
});

try {
  await parser.execute();
} catch (error) {
  if (error instanceof CommandLineValidationError) {
    console.error(error.message);
    process.exitCode = 1;
  } else {
    throw error;
  }
}

Strict invalid input rejects with the aggregate while clean --help resolves. The application sets process.exitCode; the library does not call process.exit().

## Command Grouping and Subcommands Pattern

### When to Use It

This pattern is useful when you have multiple related commands that can share common configurations or functionalities. It allows developers to group commands together and provide a clear structure for command hierarchies, facilitating better organization and usability.

### Code Example

```typescript
import { CommandLineParser, ICommand } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'project-cli' });

const buildCommand: ICommand = {
  name: 'build',
  description: 'Build the project',
  options: [
    {
      name: 'environment',
      type: 'string',
      required: true,
      description: 'Specify the environment to build for',
    },
  ],
  handler: async options => {
    console.log(`Building for environment: ${options.environment}`);
  },
};

const testCommand: ICommand = {
  name: 'test',
  description: 'Run tests',
  options: [
    {
      name: 'watch',
      type: 'boolean',
      description: 'Run tests in watch mode',
    },
  ],
  handler: async options => {
    console.log(`Running tests in watch mode: ${options.watch ? 'enabled' : 'disabled'}`);
  },
};

const deployCommand: ICommand = {
  name: 'deploy',
  description: 'Deploy the project',
  options: [
    {
      name: 'target',
      type: 'string',
      required: true,
      description: 'Deployment target',
    },
  ],
  handler: async options => {
    console.log(`Deploying to: ${options.target}`);
  },
};

parser.addCommand(buildCommand);
parser.addCommand(testCommand);
parser.addCommand(deployCommand);

await parser.execute();
```

Explanation ​

This pattern defines three commands: build, test, and deploy. Each command is associated with its own options and handler functions. Developers can easily extend this set by adding more commands as needed while maintaining a clear structure with meaningful descriptions.

Caveats or Performance Considerations ​

While organizing commands into groups improves clarity, it's crucial to ensure that the command names remain unique to avoid conflicts. Implementing too many nested levels can also complicate the command execution process and lead to a complex hierarchy that may be harder for users to navigate.

Multi-Value Options with Validation Pattern ​

When to Use It ​

This pattern is ideal when you need to handle command line options that can accept multiple values and require specific validations. It allows for clean handling of scenarios where multiple inputs are needed for a single option, such as file paths or tags.

Code Example ​

typescript
import { CommandLineParser, ICommand, ICommandOption } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'file-cli' });

const uploadCommand: ICommand = {
  name: 'upload',
  description: 'Upload files to the server',
  options: [
    {
      name: 'files',
      type: 'string',
      multiple: true,
      required: true,
      description: 'List of files to upload',
    },
    {
      name: 'overwrite',
      type: 'boolean',
      description: 'Overwrite existing files on the server',
    },
  ],
  handler: async options => {
    console.log(`Uploading files: ${options.files.join(', ')}`);
    if (options.overwrite) {
      console.log('Overwrite mode is enabled.');
    }
  },
};

parser.addCommand(uploadCommand);

await parser.execute();

Explanation ​

In this example, the upload command accepts a files option that can handle multiple file paths. Developers can leverage the multiple property in the ICommandOption interface to specify that the files option can accept more than one value, enabling flexible command line input handling.

Caveats or Performance Considerations ​

When allowing multiple values, ensure proper validation for the provided inputs to avoid errors during execution. Additionally, be aware that extensive validation logic can introduce overhead in processing time, especially if many options are present.

Custom Validators Pattern ​

When to Use It ​

This pattern is beneficial when you require additional validation logic beyond the built-in type checks provided by the command line parser. It allows developers to create custom validation rules tailored to specific use cases.

Code Example ​

typescript
import { CommandLineParser, ICommand } from 'blendsdk/cmdline';

const isPositiveNumber = (value: number) => {
  return value > 0 || 'Value must be a positive number';
};

const parser = new CommandLineParser({ name: 'math-cli' });

const squareCommand: ICommand = {
  name: 'square',
  description: 'Calculate the square of a number',
  options: [
    {
      name: 'number',
      type: 'number',
      required: true,
      description: 'The number to square',
      validator: isPositiveNumber,
    },
  ],
  handler: async options => {
    const result = options.number * options.number;
    console.log(`Square of ${options.number}: ${result}`);
  },
};

parser.addCommand(squareCommand);

await parser.execute();

Explanation ​

In this example, the square command has a number option that is validated by the custom isPositiveNumber function. This provides direct feedback to the user if an invalid value is provided, enhancing the robustness of the command line interface.

Caveats or Performance Considerations ​

Custom validators can introduce complexity, especially if numerous validators are added. Ensure they are efficient to prevent performance degradation during parsing. Maintain a consistent error messaging strategy for improved user experience.

Integration with Other Libraries Pattern ​

When to Use It ​

This pattern is particularly valuable when you need to integrate with other libraries (e.g., for logging, configuration management, or making HTTP requests) within a command-line tool. This approach allows for layered functionalities where different parts of the application can work cohesively.

Code Example ​

typescript
import { CommandLineParser, ICommand } from 'blendsdk/cmdline';
import axios from 'axios'; // Requires axios to be installed

const parser = new CommandLineParser({ name: 'api-cli' });

const fetchDataCommand: ICommand = {
  name: 'fetch',
  options: [
    {
      name: 'url',
      type: 'string',
      required: true,
      description: 'API endpoint to fetch data from',
    },
  ],
  handler: async options => {
    try {
      const response = await axios.get(options.url);
      console.log('Data fetched:', response.data);
    } catch (error) {
      console.error(`Error fetching data: ${error.message}`);
    }
  },
};

parser.addCommand(fetchDataCommand);

await parser.execute();

Explanation ​

Here, the fetch command uses the Axios library to make an HTTP GET request to a specified URL. By integrating external libraries, the command can accomplish network operations directly from the command line.

Caveats or Performance Considerations ​

When integrating with external libraries, ensure that proper error handling is implemented for network requests. Additionally, consider the performance implications of external calls, especially in a command-line context where responsiveness is crucial for user interaction.

Command Aliasing Pattern ​

When to Use It ​

This pattern can be useful when you want to offer alternative names for commands. It enhances user experience by allowing flexibility in command invocation, catering to different developer preferences or naming conventions.

Code Example ​

typescript
import { CommandLineParser, ICommand } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'alias-cli' });

const greetCommand: ICommand = {
  name: 'greet',
  aliases: ['hi', 'hello'], // Aliases for the greet command
  options: [
    {
      name: 'user',
      type: 'string',
      description: 'The user to greet',
    },
  ],
  handler: async options => {
    console.log(`Greetings, ${options.user || 'stranger'}!`);
  },
};

parser.addCommand(greetCommand);

await parser.execute();

Explanation ​

In this example, the greet command can also be invoked using its aliases hi and hello. This enhances usability by providing multiple ways to execute the same functionality.

Aliases select the canonical command and handler state. Strict mode matches their declared casing exactly; legacy mode uses case-normalized lookup. Canonical names and aliases must remain unique after normalization.

Caveats or Performance Considerations ​

While this pattern is beneficial, ensure that alias handling mechanics do not create conflicts with existing command names. Managing a large number of aliases can complicate the command line interface and increase confusion among users.

# cmdline Best Practices

---

## Do / Don't Pairs

### 1. Proper Error Handling

❌ **Wrong**: Ignoring errors in command handlers.

```typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'run',
  handler: async () => {
    // No error handling
    throw new Error('Something went wrong');
  },
});

await parser.execute();
```

✅ Correct: Implement error handling in command handlers.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'run',
  handler: async () => {
    try {
      // Logic that could throw
      throw new Error('Something went wrong');
    } catch (error) {
      console.error(`Error: ${(error as Error).message}`);
      throw error; // Rethrow or handle accordingly
    }
  },
});

await parser.execute();

Why: Proper error handling prevents unhandled exceptions and provides meaningful feedback to the user, improving the user experience.

2. Use Validators Effectively ​

❌ Wrong: Relying solely on types without validation.

typescript
import { CommandLineParser, ICommandOption } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'process',
  options: [
    {
      name: 'count',
      type: 'number', // No validation
    },
  ],
  handler: async options => {
    console.log(`Count: ${options.count}`);
  },
});

await parser.execute();

✅ Correct: Always use validators for enhanced input validation.

typescript
import { CommandLineParser, ICommandOption } from 'blendsdk/cmdline';

const isPositiveNumber = (value: number) => value > 0 || 'Value must be positive';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'process',
  options: [
    {
      name: 'count',
      type: 'number',
      validator: isPositiveNumber, // Ensures value is valid
    },
  ],
  handler: async options => {
    console.log(`Count: ${options.count}`);
  },
});

await parser.execute();

Why: Validators check the integrity of user inputs, ensuring the application behaves predictably and safely.

3. Keep Commands and Options Simple ​

❌ Wrong: Complex nested command structures.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'complexCommand',
  options: [
    {
      name: 'subCommand1',
      options: [{ name: 'option1', type: 'string' }],
    },
    {
      name: 'subCommand2',
      options: [{ name: 'option2', type: 'number' }],
    },
  ],
  handler: async () => {
    // Complex logic
  },
});

✅ Correct: Maintain clarity and single responsibility by flattening structures.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'first',
  options: [{ name: 'name', type: 'string', required: true }],
  handler: async options => {
    console.log(`First: ${options.name}`);
  },
});

parser.addCommand({
  name: 'second',
  options: [{ name: 'value', type: 'number', required: true }],
  handler: async options => {
    console.log(`Second: ${options.value}`);
  },
});

await parser.execute();

Why: Keeping command structures simple improves maintainability and reduces user confusion.

4. Provide Meaningful Help Messages ​

❌ Wrong: Vague descriptions for options and commands.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'run',
  options: [{ name: 'x', type: 'string' }], // No description
  handler: async () => {},
});

await parser.execute();

✅ Correct: Always provide detailed descriptions.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'run',
  description: 'Executes the run command to start the application',
  options: [
    {
      name: 'x',
      type: 'string',
      description: 'Specifies the input parameter for running the command',
    },
  ],
  handler: async () => {},
});

await parser.execute();

Why: Clear descriptions empower users to understand options, improving usability and reducing errors.

Anti-Patterns ​

1. Ignoring CLI Input Edge Cases ​

Common mistake: Failing to handle empty inputs or incorrect argument types can lead to crashes.

typescript
// Failing to handle no input
const input = process.argv[2]; // No validation
if (!input) {
  console.error('Input is required!');
  process.exitCode = 1;
}

Mitigation: ​

Prefer strict: true so parser-owned failures reject before the handler. Catch CommandLineValidationError at the application boundary and set process.exitCode; do not make library code terminate the process.

2. Overly Complex Command Logic ​

Common mistake: Implementing complicated logic within command handlers can lead to difficulty in maintenance and testing.

typescript
// Complex command logic
parser.addCommand({
  name: 'doSomething',
  handler: async options => {
    // Multiple nested if statements and complex processing flow
  },
});

Mitigation: ​

Break complex logic into smaller functions, keep command handlers focused on parsing.

3. Not Leveraging Asynchronous Benefits ​

Common mistake: Using synchronous code for I/O operations can block the event loop and degrade performance.

typescript
// Synchronous I/O operation
fs.readFileSync('./file.txt');

Mitigation: ​

Always prefer asynchronous methods using async/await for better performance.

Performance Tips ​

1. Value Caching ​

For commands that utilize frequent operations with the same inputs, cache results to reduce processing times.

typescript
const cache = {};

const compute = input => {
  if (cache[input]) {
    return cache[input]; // Return cached value
  }
  const result = performExpensiveOperation(input);
  cache[input] = result; // Cache the result
  return result;
};

2. Minimize Options ​

Limit the number of options per command to reduce parsing overhead. Consider using global options for common parameters shared across commands.

3. Use Batch Processing ​

If applicable, process multiple entries in a single execution to avoid repeated parsing and validation.

typescript
// Process multiple commands in a single execution
const entries = ['entry1', 'entry2', 'entry3'];
await Promise.all(entries.map(entry => processEntry(entry)));

Security Considerations ​

  1. Input Sanitization: Always validate and sanitize user inputs to prevent injection attacks. For example, use proper type-checking functions on all input values.

  2. Limit Command Options: Be cautious about exposing sensitive functionalities through command options and ensure proper authentication where applicable.

  3. Error Information: Avoid revealing sensitive internal error details in help output or error messages to minimize information leakage.

  4. Dependencies: Regularly audit and update dependencies to mitigate vulnerabilities that could compromise the command line tool.

How do I handle errors gracefully in commands? ​

Separate parser-owned input failures from exceptions thrown by command handlers.

Solution ​

Enable strict mode and catch CommandLineValidationError around execute(). The parser blocks the handler, keeps specific issues in order, and leaves exit policy to the application.

Code Example ​

typescript
import { CommandLineParser, CommandLineValidationError } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app', strict: true });

parser.addCommand({
  name: 'run',
  options: [
    {
      name: 'input',
      type: 'string',
      required: true,
    },
  ],
  handler: async options => {
    console.log(`Processing input: ${options.input}`);
  },
});

try {
  await parser.execute();
} catch (error) {
  if (error instanceof CommandLineValidationError) {
    console.error(error.message);
    process.exitCode = 1;
  } else {
    throw error;
  }
}

## Common Errors

The examples below describe strict mode (`strict: true`). Strict parser-owned failures reject with
`CommandLineValidationError`; inspect its ordered `issues` array. With strict mode omitted or
`false`, v5 retains legacy permissive/help-and-resolve behavior. Similarity hints never correct or
execute misspelled input.

### Argument Parsing Errors

1. **Error Message / Symptom**: `Malformed argument [--option=]: missing value`
   - **Cause**: An option was provided but a value was not supplied.
   - **Fix**:

   ```typescript
   import { CommandLineParser } from 'blendsdk/cmdline';

   const parser = new CommandLineParser({ name: 'app' });

   parser.addCommand({
     name: 'sample',
     options: [
       {
         name: 'option',
         type: 'string',
         description: 'An example option',
       },
     ],
     handler: async () => {
       // Command logic
     },
   });

   await parser.execute(); // Ensure to always provide a value like --option=value
   ```

  1. Error Message / Symptom: Unknown option [--unknown] for command [command-name]

    • Cause: The user has provided an option that does not exist for the specified command.
    • Fix:
    typescript
    import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'command-name',
  options: [
    {
      name: 'known-option',
      type: 'boolean',
      description: 'A known option',
    },
  ],
  handler: async () => {
    // Command logic
  },
});

await parser.execute(); // Ensure use of valid options like --known-option

Validation Errors ​

  1. Error Message / Symptom: Missing required option [--option]

    • Cause: A required option was not supplied when executing the command.
    • Fix:
    typescript
    import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

parser.addCommand({
  name: 'config',
  options: [
    {
      name: 'required-option',

      description: 'An essential option',

  ],

    // Command logic
  },
});

await parser.execute(); // Ensure to pass --required-option='value'

  2. Error Message / Symptom: Invalid value provided for option [--option], required [type]

    • Cause: The user provided a value that does not match the expected type.
    • Fix:
    typescript
    import { CommandLineParser } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'app' });

    {
      name: 'number',

    },
  ],

    console.log(`Calculating square of ${options.number}`);
  },

await parser.execute(); // Ensure the correct value type is provided

Debugging Strategies ​

  1. Check Command and Option Registration:

    • Verify that commands and their options are registered correctly. Print the commands after registration to check:
    typescript
    console.log(parser.commands);

  2. Use Console Logging:

    • Add console.log statements in command handlers to track the execution flow and verify whether the expected code paths are being hit.
    typescript
    console.log('Command executed, options:', options);

  3. Utilize Error Handling:

    • Wrap your command logic in try/catch blocks to catch and log errors. This provides insights when something goes wrong.
    typescript
    try {
  await parser.execute();
} catch (error) {
  console.error('Error executing command:', error);
}

  4. Mock External Dependencies:

    • If your command depends on external services or libraries, use mocking to ensure that the failures are isolated to the command logic.
typescript
import { MockedFunction } from 'vitest';

const mockFunction: MockedFunction<any> = jest.fn();

Known Pitfalls ​

  1. Neglecting Required Options: Always ensure required options are clearly documented and validations are in place to provide feedback to users. Use default values when possible to minimize errors.

  2. Ignoring Command Aliases: Be cautious of command naming conflicts when using aliases. Make sure aliases reference the correct command to avoid confusion.

  3. Failing to Document Options: Every option added to a command should include a clear description, so users understand what value they need to provide.

  4. Underestimating Edge Cases: Always anticipate potential edge cases, such as invalid formats or empty values, and ensure your logic gracefully handles them.

  5. Overly Complex Command Logic: Keep command handlers simple. If a command's logic spans multiple responsibilities or complex structures, consider breaking it down into smaller, reusable functions.

By following the strategies, recognizing pitfalls, and addressing common errors, you can enhance both the reliability of the blendsdk/cmdline and the overall user experience in your applications.

Error Handling ​

Handle Errors Gracefully ​

Catch strict parser rejection at the application boundary.

typescript
import { CommandLineParser, CommandLineValidationError } from 'blendsdk/cmdline';

const parser = new CommandLineParser({ name: 'error-cli', strict: true });

parser.addCommand({
  name: 'run',
  options: [{ name: 'input', type: 'string', required: true }],
  handler: async options => console.log(`Running with input: ${options.input}`),
});

try {
  await parser.execute();
} catch (error) {
  if (error instanceof CommandLineValidationError) {
    console.error(error.message);
    process.exitCode = 1;
  } else {
    throw error;
  }
}

HTTP Requests ​

Fetch Data Command ​

Using axios to fetch data from an API.

typescript
import { CommandLineParser } from 'blendsdk/cmdline';
import axios from 'axios';

const parser = new CommandLineParser({ name: 'fetch-cli' });

parser.addCommand({
  name: 'fetch',
  options: [{ name: 'url', type: 'string', required: true, description: 'API endpoint' }],

      const response = await axios.get(options.url);

      console.error('Error fetching data:', error.message);
    }
  },
});

await parser.execute(); // Example: node script.js fetch --url=https://example.com/api
