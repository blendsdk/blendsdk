dbcore Overview ​

What It Is ​

blendsdk/dbcore is a TypeScript library that provides essential abstractions and statement builders for managing database operations in the BlendSDK ecosystem. It enables the construction of type-safe SQL queries for CRUD (Create, Read, Update, Delete) operations and abstracts the complexities of database interactions.

Key Features ​

  • Type-Safe SQL Statement Builders: Provides fluent interfaces for constructing SQL statements for various operations, ensuring type safety.
  • Support for CRUD Operations: Enables the creation of statements for inserting, updating, deleting, and querying data.
  • Fluent API: Allows method chaining for building complex queries through an intuitive interface.
  • Expression-based Filtering: Incorporates powerful expression builders to create dynamic WHERE clauses for complex filters.
  • Return Field Management: Supports returning specific fields after operations using RETURNING clauses.
  • Flexibility Across Databases: Abstracts database operations, allowing easy extension to different database backends.

When To Use ​

  • Enterprise Applications: Ideal for building scalable applications with complex data operations that require a robust database interaction layer.
  • Data-driven Web Applications: Perfect for applications that need to manage extensive data interactions efficiently, such as user management systems.
  • Microservices Architecture: Useful in microservices that manage their own data persistence and require a consistent approach to database operations.

Architecture ​

blendsdk/dbcore follows a modular architecture that utilizes several key design patterns:

  • Builder Pattern: Employed in statement builders (e.g., InsertStatement, UpdateStatement, DeleteStatement) to construct SQL statements through method chaining.
  • Factory Pattern: Used in creating data services (QueryDataService) that encapsulate query logic specific to a database table.
  • Abstract Class Pattern: Defines abstract base classes (e.g., Database, CRUDStatement) that enforce contract methods for concrete implementations, ensuring consistency across different database types.

This architecture simplifies integrating various database backends while maintaining a seamless developer experience.

Dependencies ​

  • Peer Dependencies:

    • typescript: Required for TypeScript strict mode support.

  • Direct Dependencies:

    • blendsdk/expression: A companion package for handling query expressions and compilation.

Minimum Example ​

Here's a simple example demonstrating how to use blendsdk/dbcore to insert a new user into a database:

typescript
import { Database } from 'blendsdk/dbcore';
import { InsertStatement } from 'blendsdk/dbcore';

class MyDatabase extends Database {
  // Implement required database methods here
}

// Create a new database instance

// Insert a new user

  const insertStmt = db.insert<{ name: string; email: string }>('users');
  
  const result = await insertStmt
    .values({ name: 'John Doe', email: 'john@example.com' })
    .returning(['id'])
    .executeReturnSingle();

  console.log(result); // Logs the inserted user ID
}

createUser().catch(console.error);

CRUD Statement Class ​

What It Is ​

The CrudStatement class is an abstract base class for constructing SQL statements that perform Create, Read, Update, and Delete (CRUD) operations. It encapsulates shared logic and behavior among different CRUD operation types.

How It Works ​

By extending the Statement class, CrudStatement provides common properties and methods for managing values and return fields, including the ability to specify columns to return after an operation. Concrete implementations like InsertStatement, UpdateStatement, and DeleteStatement inherit from it, each implementing their specific SQL syntax.

Complete Example ​

typescript
import { Database, CrudStatement } from 'blendsdk/dbcore';

class InsertUser extends CrudStatement<{ id: number; name: string; email: string }> {
  protected buildQuery(): string {
    const columns = Object.keys(this._values).join(', ');
    const placeholders = Object.keys(this._values).map(key => `:${key}`).join(', ');
    return `INSERT INTO ${this.tableName} (${columns}) VALUES (${placeholders}) RETURNING *`;
  }

  protected buildParameters(): Record<string, any> {
    return this._values;
  }
}

// Usage
const db = new Database(/* connection config */);
const stmt = new InsertUser('users', db);
const result = await stmt
  .values({ name: 'John Doe', email: 'john@example.com' })
  .returning(['id'])
  .executeReturnSingle();

console.log(result);

Update Statement Class ​

What It Is ​

The UpdateStatement class extends the FilterableStatement class to build SQL UPDATE statements that modify existing records in a database based on specified criteria. This class allows for dynamic construction of updates while handling filtering and return fields.

How It Works ​

By leveraging the functionality of CrudStatement, UpdateStatement enables the specification of what fields to update, apply filters for identifying records, and handle returning columns upon completion. This allows the developer to easily compose complex update operations through an expressive API.

Complete Example ​

typescript
import { Database, UpdateStatement } from 'blendsdk/dbcore';

class UserUpdate extends UpdateStatement<{ name: string; email: string }, { id: number }> {
  protected buildQuery(): string {
    const setClauses = Object.keys(this._values).map(key => `${key} = :${key}`).join(', ');
    return `UPDATE ${this.tableName} SET ${setClauses} WHERE id = :id RETURNING *`;
  }

  protected buildParameters(): Record<string, any> {
    return { ...this._values, id: this._filter.id };
  }
}

// Usage
const db = new Database(/* connection config */);
const stmt = new UserUpdate('users', db);
const updatedUser = await stmt
  .values({ name: 'John Updated' })
  .filter({ id: 123 })
  .returning(['id', 'name'])
  .executeReturnSingle();

console.log(updatedUser);

Query Data Service Class ​

What It Is ​

The QueryDataService class provides a structured way to interact with a specific database table, enabling common query operations like fetching records by ID or expression. This class abstracts away the underlying query logic and provides a more convenient interface for data access.

How It Works ​

By extending DataServiceBase, QueryDataService offers methods for executing queries that return either single or multiple records. It utilizes the expression builder from blendsdk/expression for constructing type-safe queries, promoting strong typing across data interactions.

Complete Example ​

typescript
import { Database } from 'blendsdk/dbcore';

class UserService extends QueryDataService<{ id: number; name: string; email: string }> {

dbcore Advanced Patterns ​

Transaction Management with Statement Chaining ​

When to Use ​

This pattern is useful when you need to execute multiple CRUD operations in a single transaction, ensuring that all operations are treated as a single unit of work. If any operation fails, the entire transaction can be rolled back, maintaining data integrity.

Complete Example ​

typescript
import { Database, Transaction } from 'blendsdk/dbcore';
import { InsertStatement } from 'blendsdk/dbcore';
import { UpdateStatement } from 'blendsdk/dbcore';

class MyDatabase extends Database {
  async connect() {
    // Implement connection logic
  }

  async disconnect() {
    // Implement disconnection logic
  }

  async executeQuery<R>(query: string, params?: Record<string, any>): Promise<QueryResult<R> | null> {
    // Implement query execution logic
    return null; // Replace with actual query result
  }
}

// Create a new database instance
const db = new MyDatabase();

async function runTransaction() {
  return await db.withTransaction(async (transactionDb) => {
    const insertStmt = transactionDb.insert<{ name: string; email: string }>('users');
    
    const newUser = await insertStmt
      .values({ name: 'John Doe', email: 'john@example.com' })
      .returning(['id'])
      .executeReturnSingle();
    
    const updateStmt = transactionDb.update<{ email: string }, { id: number }>('users');
    
    await updateStmt
      .values({ email: 'john.doe@example.com' })
      .filter({ id: newUser?.id })
      .executeReturnCount();

    return newUser;
  });
}

runTransaction().catch(console.error);

Explanation ​

Using the withTransaction method allows you to execute multiple statements such that if one fails, all previous statements are rolled back, ensuring that the database remains in a consistent state. This pattern is particularly useful in scenarios like user registrations, where both the INSERT of a new user and an UPDATE on related data need to succeed together.

Caveats ​

  • Ensure that each operation is set up correctly to avoid failed transactions.
  • Be cautious of locks and potential deadlocks when using transactions extensively.

dbcore Best Practices ​

Do / Don't Pairs ​

Do: Use Type-safe Values in Insert Statements ​

When inserting data into the database, utilize TypeScript's type system to ensure that the values being passed are of the correct type.

typescript
import { Database } from 'blendsdk/dbcore';
import { InsertStatement } from 'blendsdk/dbcore';

async function createUser(db: Database) {
  const insertStmt = db.insert<{ name: string; email: string }>('users');
  
  const newUser = await insertStmt
    .values({ name: 'Alice', email: 'alice@example.com' })
    .returning(['id'])
    .executeReturnSingle();

  console.log(newUser);
}
typescript
// ❌ Wrong usage
const insertStmt = db.insert('users'); // Missing type safety
insertStmt.values({ name: 'Alice', email: 'not-an-email' }); // This could lead to runtime errors

Why It's Problematic: Omitting type definitions can lead to database errors or unexpected behavior since invalid data may be accepted at runtime.

Do: Handle Errors Gracefully ​

Wrap your database operations in error handling to catch any issues that arise during execution.

typescript
async function fetchUser(db: Database, userId: number) {
  try {
    const result = await db.from('users')
      .select(['id', 'name'])
      .byExpression(query => query.where('id').equals(userId))
      .executeReturnSingle();
    console.log(result);
  } catch (error) {
    console.error('Error fetching user:', error);
  }
}
typescript
// ❌ Wrong usage
const result = db.from('users').select().executeReturnSingle(); // No error handling

Why It's Problematic: Not handling errors can lead to the application crashing or leaving the user without feedback, complicating debugging and user experience.

Do: Use Fluent API for Complex Queries ​

Leverage the fluent API provided by statement builders to create complex queries in a readable and maintainable way.

typescript
async function updateUserEmail(db: Database, userId: number, newEmail: string) {
  const updateStmt = db.update<{ email: string }, { id: number }>('users');

// ❌ Wrong usage
const updateStmt = db.update('users');
updateStmt.values({ email: 'invalid-email' }).execute(); // No conditions, resulting in bulk update

Why It's Problematic: Not applying filters or conditions could unintentionally modify multiple records, leading to data integrity issues.

Anti-Patterns ​

Global Configuration for Database Connections ​

Avoid global configurations for database connections, which can lead to complications with state management, especially in a modular application.

typescript
let dbInstance: Database;

function configureDatabase(config: DatabaseConfig) {
  dbInstance = new Database(config);
}

// Usage in multiple modules can lead to unexpected states

Recommendation: Create a new instance of the Database class wherever needed instead of relying on global state.

Unused Imports in Statement Builders ​

Unintentionally importing unused classes or types can clutter your code and lead to confusion.

typescript
import { Database, InsertStatement, unusedType } from 'blendsdk/dbcore'; // ❌ Unused import

const insertStmt = new InsertStatement('users', new Database(/* config */));

Recommendation: Always review imports and remove those that aren't utilized to maintain code clarity.

Performance Tips ​

When inserting multiple records, utilize batch insertions to minimize database round trips.

typescript

    await insertStmt
      .values(user)
      .execute();
  }
}

Optimize Query Execution ​

# dbcore Troubleshooting

---

## Common Errors

### Database Connection Error
**Error Message / Symptom**: `Connection to database failed: ...`  
**Cause**: This can occur due to incorrect connection parameters (host, database name, user, password), or the database server might be down.  
**Fix**:
1. Verify the connection parameters provided to the `Database` instance.
2. Check if the database server is running and accessible.
3. Example code to set parameters correctly:

```typescript
import { Database } from 'blendsdk/dbcore';

const db = new Database({
  host: 'localhost',
  database: 'mydb',
  user: 'admin',
  pass: 'secure_password',
});

await db.connect().catch(error => console.error('Database connection error:', error));

Query Execution Error ​

Error Message / Symptom: SQL error: syntax error at or near "..."
Cause: This suggests that the SQL syntax is invalid, perhaps due to malformed queries constructed in the statement builders.
Fix:

  1. Check the SQL query generated by your statement builders for correctness.
  2. Use console logs to output the constructed query before it is executed.
  3. Example of debugging the executed query:
typescript
const result = await insertStmt.execute().catch(error => {
  console.error('Query execution error:', error);
});
console.log(insertStmt.buildQuery()); // Log generated query

TypeError on Method Call ​

Error Message / Symptom: TypeError: Cannot read property '...' of undefined
Cause: This likely happens due to a failure to set necessary parameters or variables that the methods depend on, leading to unexpected undefined values.
Fix:

  1. Ensure that all properties required by methods (like filter or values) are properly initialized before calling.
  2. Example initialization:
typescript
const insertStmt = db.insert<{ name: string; email: string }>('users');
insertStmt.values({ name: 'Alice', email: 'alice@example.com' }); // Ensure values are set
await insertStmt.execute().catch(error => console.error('Insert error:', error));

Debugging Strategies ​

  1. Verbose Logging: Implement verbose logging for SQL queries to diagnose issues with syntax and parameters. Print both the generated queries and any parameters being used.
  2. Unit Tests: Write unit tests using Vitest or a similar framework to check individual components of your database logic. Ensure each method works as expected in isolation.
  3. Error Handling: Use try/catch blocks around your asynchronous operations to capture and log errors effectively so that you can understand what went wrong.
  4. Connect to the Database Manually: Use a database management tool to manually connect using the credentials and settings you are using in your application to confirm they work.

Known Pitfalls ​

  • Lack of Parameterization: Ensure all input values passed to queries are parameterized to prevent SQL injection vulnerabilities and to improve query performance.

  • Incorrect Type Mappings: When using TypeScript, ensure that mappings in statements align correctly with the database schema, particularly with types (e.g., strings should not be mapped to integers).

  • Not Handling Asynchronous Code: Remember to always handle asynchronous calls with await or then/catch structures; neglecting this can cause unhandled promise rejections.

  • Not Closing Connections: Always ensure that database connections are closed properly after use to avoid exhausting connection pools.

  • Underestimating Transactions: Utilize transactions when performing multiple operations that should succeed or fail as a unit. Failing to do this can lead to inconsistent data states in the database.

By recognizing these common issues, leveraging effective debugging strategies, and being aware of potential pitfalls, you can successfully troubleshoot problems that arise when working with the blendsdk/dbcore package.
