react Overview ​

What It Is ​

blendsdk/react is a React component and hook library designed for building enterprise-grade applications with the BlendSDK. It provides reusable components and hooks that facilitate seamless integration of features such as global loading indicators, internationalization, and authentication.

Key Features ​

  • Global Loader: A full-screen overlay with a customizable CSS-only spinner and optional messages.
  • Internationalization (i18n): A provider and hook for managing translations, locale switching, and lazy loading of translation resources.
  • Type Safety: Full TypeScript support for all components and hooks, ensuring robust and maintainable code.
  • Configurable Components: Extensive configuration options for visual elements and behaviors.
  • Zero Dependencies: The library relies solely on React, making it lightweight and straightforward to integrate.

When To Use ​

  • When developing complex web applications that require a robust internationalization strategy.
  • When needing a consistent loading state indicator across multiple components or pages.
  • When building applications on the BlendSDK, looking to leverage optimized React components that integrate with various Blend features.
  • When type safety and maintainability are a priority in your project's development lifecycle.

Architecture ​

The blendsdk/react package is structured around a modular architecture utilizing familiar React patterns such as Context, Provider, and Hooks. Key design patterns include:

  • Context & Provider Pattern: For managing shared state, such as authentication and loading indicators.
  • Hook Pattern: To encapsulate logic for consuming context and providing convenient access to state and functions.
  • Component-Based Structure: Encourages the reuse of UI components across applications, promoting a consistent user experience.

Dependencies ​

Peer Dependencies ​

  • react: ^19.0.0
  • react-dom: ^19.0.0
  • react-router: ^7.0.0 (optional)
  • typescript: ^5.6.0

Internal Dependencies ​

  • blendsdk/i18n: ^5.42.0

react Core Concepts ​

Global Loader ​

What It Is ​

The Global Loader is a reusable component that displays a full-screen overlay with a customizable CSS spinner and optional text. It provides visual feedback to users during asynchronous operations, such as data fetching.

How It Works ​

The Global Loader is implemented via a Context and a Provider. The GlobalLoaderProvider captures configuration during mount, allowing child components to access its state through the useGlobalLoader hook. You can show or hide the loader and set messages dynamically.

Complete Example ​

typescript
import React from 'react';
import { GlobalLoaderProvider, useGlobalLoader } from 'blendsdk/react';

function App() {
  return (
    <GlobalLoaderProvider config={{ spinnerColor: '#25b09b' }}>
      <MyPage />
    </GlobalLoaderProvider>
  );
}

function MyPage() {
  const { showLoader, setText } = useGlobalLoader();

  const handleLoadData = async () => {
    setText("Loading data…");
    showLoader(true);
    // Simulating data fetch
    await new Promise(resolve => setTimeout(resolve, 2000));
    showLoader(false);
  };

  return <button onClick={handleLoadData}>Load Data</button>;
}

Internationalization (i18n) ​

What It Is ​

The Internationalization (i18n) module provides a way to manage translations within a React application. It equips developers with tools for locale switching and lazy translation loading, making it easy to build multilingual applications.

How It Works ​

The I18nProvider wraps the application and provides the context for translations. Any component can access translation functions and the current locale using the useTranslations hook. The translations are loaded via a specified loader function asynchronously.

Complete Example ​

typescript
import React from 'react';
import { GlobalLoaderProvider, I18nProvider, useTranslations } from 'blendsdk/react';

async function fetchTranslations(locale: string) {
  const response = await fetch(`/api/translations/${locale}`);
  return response.json();
}

function App() {
  return (
    <GlobalLoaderProvider>
      <I18nProvider loader={fetchTranslations} defaultLocale="en">
        <MyComponent />
      </I18nProvider>
    </GlobalLoaderProvider>
  );
}

function MyComponent() {
  const { t, setLocale } = useTranslations();

  return (
    <div>
      <h1>{t('welcome.message')}</h1>
      <button onClick={() => setLocale('fr')}>Switch to French</button>
    </div>
  );
}

Key Methods/Properties Table ​

Authentication ​

What It Is ​

The Authentication module provides components and hooks to facilitate user authentication in BlendSDK applications. It supports BFF (Backend for Frontend) authentication with OpenID Connect (OIDC) and includes utilities for managing user sessions.

How It Works ​

The AuthProvider component manages authentication state and exposes it through the useAuth hook. Configuration options are merged with defaults, providing flexibility for endpoint paths and behaviors. The module supports token refresh to maintain user sessions.

Complete Example ​

typescript
import React from 'react';
import { AuthProvider, useAuth } from 'blendsdk/react';

const authConfig = {
  basePath: '/api/auth',
  autoRefresh: true,
};

function App() {
  return (
    <AuthProvider config={authConfig}>
      <ProfileButton />
    </AuthProvider>
  );
}

function ProfileButton() {
  const { user, isAuthenticated, login, logout } = useAuth();

  if (!isAuthenticated) {
    return <button onClick={() => login()}>Sign In</button>;
  }

  return <button onClick={() => logout()}>Sign Out ({user?.sub})</button>;
}

react Advanced Patterns ​

Advanced Loading States with Global Loader and Auth ​

When to Use ​

This pattern is ideal when you need to manage a global loading state that is aware of user authentication status. For instance, it can be used during data fetching operations that are dependent on the user being logged in, such as loading user-specific resources.

Complete Code Example ​

typescript
import React, { useEffect } from 'react';
import { GlobalLoaderProvider, useGlobalLoader } from 'blendsdk/react';
import { AuthProvider, useAuth } from 'blendsdk/react';

const authConfig = {
    basePath: '/api/auth',
    autoRefresh: true,
};

function App() {
    return (
        <GlobalLoaderProvider>
            <AuthProvider config={authConfig}>
                <UserProfile />
            </AuthProvider>
        </GlobalLoaderProvider>
    );
}

function UserProfile() {
    const { isAuthenticated, login } = useAuth();
    const { showLoader, setText } = useGlobalLoader();

    useEffect(() => {
        const fetchUserProfile = async () => {
            if (!isAuthenticated) {
                // Optionally prompt the user to login
                login();
                return;
            }

            setText('Loading user profile...');
            showLoader(true);

            try {
                // Simulate a network request to fetch user data
                await new Promise((resolve) => setTimeout(resolve, 2000));
                // Fetch user profile logic goes here
            } catch (error) {
                console.error('Error fetching user profile:', error);
            } finally {
                showLoader(false);
            }
        };

        fetchUserProfile();
    }, [isAuthenticated, login, showLoader, setText]);

    return (
        <div>
            <h1>User Profile</h1>
            {/* Display user data here */}
        </div>
    );
}

Explanation ​

This pattern integrates the GlobalLoader with an authentication mechanism, ensuring that loading states reflect the user's authentication status. The UserProfile component checks if the user is logged in; if not, it prompts the user to log in. Once authenticated, it shows a loading spinner while fetching the user's data, providing a seamless user experience.

Caveats ​

  • Ensure that the login logic does not block the UI experience, as it might lead to infinite loading states if the user cannot log in.
  • Styling of the GlobalLoader should be sufficient to ensure visibility, especially in contexts with heavy background content.

Dynamic Locale Switching with I18n and Global Loader ​

When to Use ​

This pattern is useful when your application needs to switch languages dynamically based on user interaction, while also providing visual feedback (e.g., a loading indicator) during the locale switch.

Complete Code Example ​

typescript
import React from 'react';
import { GlobalLoaderProvider, useGlobalLoader } from 'blendsdk/react';
import { I18nProvider, useTranslations } from 'blendsdk/react';

async function fetchTranslations(locale: string) {
    const response = await fetch(`/api/translations/${locale}`);
    return response.json();
}

function App() {
    return (
        <GlobalLoaderProvider>
            <I18nProvider loader={fetchTranslations} defaultLocale="en">
                <LanguageSwitcher />
            </I18nProvider>
        </GlobalLoaderProvider>
    );
}

function LanguageSwitcher() {
    const { setLocale } = useTranslations();
    const { showLoader, setText } = useGlobalLoader();

    const changeLanguage = async (locale: string) => {
        setText('Loading translations...');
        showLoader(true);

        try {
            await new Promise((resolve) => setTimeout(resolve, 1500)); // Simulate loading time
            setLocale(locale); // Change locale
        } catch (error) {
            console.error('Error changing language:', error);
        } finally {
            showLoader(false);
        }
    };

    return (
        <div>
            <button onClick={() => changeLanguage('en')}>English</button>
            <button onClick={() => changeLanguage('fr')}>French</button>
        </div>
    );
}

Explanation ​

The LanguageSwitcher component allows users to change the application's language dynamically. The GlobalLoader is used to indicate that translations are being fetched, enhancing user feedback. When a button is clicked, it simulates a delay and changes the locale accordingly, ensuring that users know that the change is processing.

Caveats ​

  • Overuse of the loader can distract users; therefore, ensure it's only used when necessary (e.g., substantial translation changes).
  • Ensure successful translation fetching before allowing the application to resume normal operation to avoid showing untranslated text.

Composing Multiple Contexts for Enhanced Functionality ​

When to Use ​

This pattern is powerful when integrating multiple functionalities (e.g., authentication, global loading, internationalization) in a cohesive application structure. It allows for functionalities to be encapsulated in separate contexts while sharing the same component tree.

Complete Code Example ​

typescript
import React from 'react';
import { GlobalLoaderProvider, useGlobalLoader } from 'blendsdk/react';
import { AuthProvider, useAuth } from 'blendsdk/react';
import { I18nProvider, useTranslations } from 'blendsdk/react';

async function fetchTranslations(locale: string) {
    const res = await fetch(`/api/translations/${locale}`);
    return res.json();
}

const authConfig = {
    basePath: '/api/auth',
    autoRefresh: true,
};

function App() {
    return (
        <GlobalLoaderProvider>
            <AuthProvider config={authConfig}>
                <I18nProvider loader={fetchTranslations} defaultLocale="en">
                    <Dashboard />
                </I18nProvider>
            </AuthProvider>
        </GlobalLoaderProvider>
    );
}

function Dashboard() {
    const { user, isAuthenticated } = useAuth();
    const { t } = useTranslations();
    const { showLoader, setText } = useGlobalLoader();

    const loadData = async () => {
        if (!isAuthenticated) {
            console.warn('User not authenticated!');
            return;
        }

        setText(t('loading.data'));
        showLoader(true);

        try {
            await new Promise((resolve) => setTimeout(resolve, 2000)); // Simulate data fetch
            // Load user-specific data logic
        } catch (error) {
            console.error('Failed to load data:', error);
        } finally {
            showLoader(false);
        }
    };

    return (
        <div>
            <h1>{isAuthenticated ? t('dashboard.title') : t('dashboard.please_login')}</h1>
            {isAuthenticated && <button onClick={loadData}>{t('dashboard.load_data')}</button>}
        </div>
    );
}

Explanation ​

This example showcases how to compose multiple contexts in a single component tree. The Dashboard component checks the user's authentication status and allows data loading when the user is authenticated, while also integrating translation features from the I18nProvider. Each context enhances the functionality of the application, providing a rich user experience.

Caveats ​

  • Ensure that context relationships are well defined to avoid performance bottlenecks.
  • Be cautious with rendering order and dependency management to prevent delays in rendering due to nested context-dependent requests.

react Best Practices ​

Do / Don't Pairs ​

Proper Context Wrapping ​

❌ Wrong

typescript
import { useAuth } from 'blendsdk/react';

function MyComponent() {
    const { user } = useAuth();
    return <div>{user?.sub}</div>; // Error: useAuth() must be used within an <AuthProvider>
}

✅ Correct

typescript
import React from 'react';
import { AuthProvider, useAuth } from 'blendsdk/react';

const authConfig = { basePath: '/api/auth' };

function App() {
    return (
        <AuthProvider config={authConfig}>
            <MyComponent />
        </AuthProvider>
    );
}

function MyComponent() {
    const { user } = useAuth();
    return <div>{user?.sub}</div>;
}

Why? Context must be properly wrapped around components using hooks to ensure they have access to the context's state. Failing to do so leads to runtime errors that disrupt user experience.

Correctly Handling Undefined States ​

❌ Wrong

typescript
import { useAuth } from 'blendsdk/react';

function MyComponent() {
    const { user } = useAuth();
    return <p>Welcome {user.sub}</p>; // Error: Cannot read properties of undefined
}

✅ Correct

typescript
import { useAuth } from 'blendsdk/react';

function MyComponent() {
    const { user } = useAuth();
    return <p>Welcome {user ? user.sub : "Guest"}</p>;
}

Why? Accessing properties of undefined leads to runtime exceptions. Handling undefined states gracefully ensures application stability and provides a better user experience.

Anti-Patterns ​

Nested Contexts Without Separation of Concerns ​

It's common to see multiple providers nested without consideration of their contexts:

typescript
function App() {
    return (
        <AuthProvider config={authConfig}>
            <GlobalLoaderProvider>
                <I18nProvider loader={fetchTranslations}>
                    <Dashboard />
                </I18nProvider>
            </GlobalLoaderProvider>
        </AuthProvider>
    );
}

Problem: Nesting can lead to confusion over which consumer gets the correct context. It makes it harder to manage state transitions and can lead to performance issues.

Recommendation: Keep contexts separate and utilized wisely. If some components only need auth or only need i18n, it's better to keep them wrapped individually.

Using Hooks Outside of Providers ​

Using a hook like useGlobalLoader() outside of its context provider will yield runtime errors:

typescript
import { useGlobalLoader } from 'blendsdk/react';

function MyComponent() {
    const { showLoader } = useGlobalLoader(); // Error: useGlobalLoader() must be used within a <GlobalLoaderProvider>
    return <button onClick={() => showLoader(true)}>Load</button>;
}

Recommendation: Always wrap components that make use of context-dependent hooks within their respective providers to ensure they function correctly.

Performance Tips ​

Optimize Provider Re-renders ​

When using context providers, unnecessary re-renders can impact performance. Use memoization or context selectors:

typescript
const UserContext = React.createContext();

function App() {
  const user = useUser(); // Fetch user information
  return (
    <UserContext.Provider value={user}>
      <MemoizedComponent />
    </UserContext.Provider>
  );
}

const MemoizedComponent = React.memo(function Component() {
    const user = React.useContext(UserContext);
    return <div>{user.name}</div>;
});

Reasoning: Utilizing React.memo prevents re-renders of components that don’t rely on changes within the user context, improving performance.

Lazy Loading Translations ​

To improve load time, translations can be fetched lazily:

typescript
async function fetchTranslations(locale: string) {
    const response = await fetch(`/api/translations/${locale}`);
    return response.json(); // Only when needed
}

function App() {
    return (
        <I18nProvider loader={fetchTranslations} defaultLocale="en">
            {/* Application */}
        </I18nProvider>
    );
}

Reasoning: Fetching translations only when required reduces the initial load size and speeds up rendering for users.

Security Considerations ​

Avoid Exposing Sensitive Information ​

Don't expose user data or any sensitive configuration in your components or API responses. Always sanitize data and find ways to restrict access.

Use Annotations and Validations ​

Ensure to validate inputs from users and APIs. Utilize TypeScript for defining strict data models and interfaces, which helps catch errors early in the application development.

typescript
import { AuthConfig } from 'blendsdk/react';

function setupAuth(config: AuthConfig) {
    if (!config.basePath) {
        throw new Error("basePath is required"); // Explicit error handling
    }
    // Set up authentication...
}

Reasoning: Proper validation reduces the risk of unexpected behaviors and security vulnerabilities within your application.

react Troubleshooting ​

Common Errors ​

useAuth Error: "useAuth() must be used within an <AuthProvider>." ​

  • Cause: This error occurs when the useAuth hook is invoked outside of an AuthProvider component.
  • Fix: Ensure that all components using useAuth are wrapped within an AuthProvider. Here is an example:
typescript
import React from 'react';
import { AuthProvider, useAuth } from 'blendsdk/react';

const App = () => {
    const authConfig = { basePath: '/api/auth' };

    return (
        <AuthProvider config={authConfig}>
            <MyComponent />
        </AuthProvider>
    );
};

const MyComponent = () => {
    const { user } = useAuth();
    return <div>{user?.sub}</div>;
};

useGlobalLoader Error: "useGlobalLoader() must be used within a <GlobalLoaderProvider>." ​

  • Cause: This error happens when useGlobalLoader is called outside of a GlobalLoaderProvider.
  • Fix: Wrap your component tree that uses useGlobalLoader within a GlobalLoaderProvider. See the example below:
typescript
import React from 'react';
import { GlobalLoaderProvider, useGlobalLoader } from 'blendsdk/react';

const App = () => {
    return (
        <GlobalLoaderProvider>
            <MyComponent />
        </GlobalLoaderProvider>
    );
};

        setText("Loading...");
        showLoader(true);
        await new Promise(resolve => setTimeout(resolve, 2000));
        showLoader(false);
    };

    return <button onClick={handleLoadData}>Load Data</button>;
};

useTranslations Error: "useTranslations() must be used within an <I18nProvider>." ​

  • Cause: Attempting to call useTranslations outside of its required I18nProvider context.
  • Fix: Make sure to wrap your components that utilize useTranslations with an I18nProvider. Here's how:

    </I18nProvider>

    return <div>{t('welcome.message')}</div>;
};

Refreshing User Session ​

This example shows how to implement a token refresh mechanism within the component.

typescript
import React, { useEffect } from 'react';
import { AuthProvider, useAuth } from 'blendsdk/react';

const authConfig = {
  basePath: '/api/auth',
  autoRefresh: true,

      <UserProfile />
    </AuthProvider>

}
