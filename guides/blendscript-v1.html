BlendScript Course ​

This course teaches BlendScript from two viewpoints:

  1. Formula authors learn to read and write business rules.
  2. Application developers learn to validate, store, compile, and evaluate those rules in an external application.

No programming knowledge is required for Part I. Part II assumes basic TypeScript knowledge.

Learning outcomes ​

After completing the course, you can:

  • write BlendScript rules using fields, values, comparisons, IN, AND, OR, NOT, and built-ins;
  • predict how parentheses and operator precedence affect a rule;
  • handle empty, blank, and nullable values intentionally;
  • understand and correct author-facing diagnostics;
  • integrate the public blendsdk/blendscript package into a Node.js application;
  • design a schema, validate rules during authoring, compile saved source, and evaluate records safely.

Part I: Using BlendScript as a formula author ​

Lesson 1: The basic mental model ​

A BlendScript expression is a question about one record. The expression returns one value, commonly TRUE or FALSE.

Imagine an application gives BlendScript this customer record:

FieldValue
CountryNL
Age42
ActiveTRUE
CustomerNameAda

The expression:

text
Country == "NL"

asks: “Is this customer's Country equal to NL?” For the record above, the result is TRUE.

BlendScript expressions:

  • have no leading equals sign;
  • use double quotes for text;
  • use TRUE, FALSE, and NULL for special values;
  • can read only fields provided by the application;
  • cannot change data or call application functions.

Try it ​

Write a rule that is TRUE when Active is TRUE.

text
Active == TRUE

A Boolean field can also stand on its own:

text
Active

Lesson 2: Values and field names ​

BlendScript has four value kinds.

KindExamples
Text"NL", "Gold", "Ada"
Number10, -2.5, .5, 1e3
BooleanTRUE, FALSE
NullNULL

Simple field names look like identifiers:

text
Country
OrderTotal
customer_2

Use brackets when a field contains spaces or collides with a language word:

text
[Order Total]
[Customer Segment]
[AND]

Field names are exact and case-sensitive. Country and country are different fields.

Escaping a closing bracket ​

Write a closing bracket twice inside a bracketed name:

text
[Closing]]Bracket]

Lesson 3: Comparisons and membership ​

Equality ​

text
Country == "NL"
Status != "Blocked"

BlendScript does not coerce operator operands. The text "10" is not equal to the number 10. A rule can request an explicit conversion with tryNumber or text.

Number comparisons ​

text
Age >= 18
OrderTotal < 1000
Score > 0
Discount <= 25

The operators <, <=, >, and >= accept numbers only.

Membership ​

Use IN when one value may match one of several fixed choices:

text
Country IN ("NL", "BE", "DE")
Status IN ("New", "Pending", "Review")

IN contains one or more literal values. These are invalid:

text
Country IN ()
Country IN (OtherCountry)
Country IN ("NL",)

Lesson 4: Combining conditions ​

AND ​

Both sides must be TRUE:

text
Country == "NL" AND Active == TRUE

OR ​

At least one side must be TRUE:

text
Country == "NL" OR Country == "BE"

NOT ​

NOT reverses a Boolean result:

text
NOT Blocked
NOT (OrderTotal >= 1000)

Precedence ​

BlendScript evaluates operators in this order:

PriorityConstruct
1Values, fields, function calls, parentheses
2NOT
3Comparisons and IN
4AND
5OR

AND is evaluated before OR:

text
Country == "GB" OR Country == "NL" AND Active == TRUE

means:

text
Country == "GB" OR (Country == "NL" AND Active == TRUE)

Use parentheses whenever the intended grouping might not be obvious:

text
(Country == "GB" OR Country == "NL") AND Active == TRUE

Lesson 5: Text functions ​

Empty and blank values ​

FunctionTRUE when
isEmpty(value)value is NULL or empty text ""
isBlank(value)value is NULL, empty, or whitespace-only text
text
isBlank(CustomerName)
NOT isEmpty(Reference)

Searching text ​

These functions are case-sensitive:

text
contains(Description, "urgent")
startsWith(Reference, "EU-")
endsWith(FileName, ".pdf")

Changing or comparing case ​

text
lower(CountryCode) == "nl"
upper(Category) == "PRIORITY"
equalsIgnoreCase(Status, "pending")

equalsIgnoreCase is the only case-insensitive comparison.

Trimming and measuring ​

text
trim(CustomerName) == "Ada"
length(CustomerName) <= 80

trim removes whitespace only at the start and end. length counts Unicode code points, so length("😀") is 1.

Converting mixed scalar fields ​

An application can declare a scalar field when source data may preserve either text or a finite number. Convert it before using an operation that needs one concrete type:

text
tryNumber(Item) != NULL AND tryNumber(Item) > 1
text(Item) == "001"

tryNumber accepts a finite number or complete decimal text. It returns NULL for blank, invalid, partial, or non-finite numeric text. text preserves strings exactly, including leading zeroes, and formats finite numbers without locale-specific behavior. BlendScript never infers either conversion.

Lesson 6: Null, empty, and missing are different ​

NULL means the application supplied an allowed nullable field with no value:

text
OptionalCode == NULL
OptionalCode == NULL OR startsWith(OptionalCode, "EU-")

An empty string is text with zero characters:

text
OptionalCode == ""

A blank string contains only whitespace. Use isBlank to accept all three “no useful text” cases:

text
isBlank(OptionalCode)

A missing field is not NULL. Every field declared by the application must be present in the record. A missing field produces BS_MISSING_FIELD.

Lesson 7: Reading diagnostics ​

When a formula is invalid, BlendScript returns diagnostics with:

  • a stable code;
  • a human-readable message;
  • the exact source span and line/column for source problems.

Example:

text
Countri == "NL"

If the schema contains Country but not Countri, the result is BS_UNKNOWN_FIELD. BlendScript does not guess or silently correct field names.

Common author corrections:

ProblemCorrection
Formula begins with =Remove the leading equals sign
Text uses single quotesUse double quotes
Field contains spacesPut the exact field name in brackets
Types do not matchCompare values of the same declared type
A comparison is chainedCombine separate comparisons with AND
A nullable value reaches a text functionCheck for NULL first or use isEmpty/isBlank

See Troubleshooting for every diagnostic and programmer-error code.

Part I project: Customer review rule ​

Business requirement:

Review an active customer when they are in NL or BE, have an order total of at least 1,000, and have a non-blank name.

Schema supplied by the application:

FieldType
Countrystring
Activeboolean
Order Totalnumber
CustomerNamestring

One readable solution:

text
(Country == "NL" OR Country == "BE")
AND Active == TRUE
AND [Order Total] >= 1000
AND NOT isBlank(CustomerName)

An equivalent membership-based solution:

text
Country IN ("NL", "BE")
AND Active
AND [Order Total] >= 1000
AND NOT isBlank(CustomerName)

Part II: Integrating BlendScript into an external application ​

Lesson 8: Integration lifecycle ​

An external application should follow this lifecycle:

text
Author edits source
  -> validateExpression
  -> show diagnostics
  -> save source text
  -> compileExpression when loading/activating the rule
  -> evaluateExpression for each complete record
  -> application decides what the result means

BlendScript owns expression validation and evaluation. Your application owns the editor, storage, authentication, authorization, data access, actions, and result handling.

Lesson 9: Install and import the public package ​

External applications install the public umbrella package:

bash
npm install blendsdk

The public umbrella package requires Node.js 22 or newer.

Import the BlendScript subpath:

typescript
import {
  BlendScriptApiError,
  compileExpression,
  evaluateExpression,
  validateExpression,
  type CompiledExpression,
  type EvaluationResult,
  type ExpressionDiagnostic,
  type ExpressionOptions,
  type ExpressionValue,
  type ValidationResult,
} from 'blendsdk/blendscript';

The direct @blendsdk/blendscript workspace is private and is intended for the BlendSDK monorepo.

Lesson 10: Design the schema ​

The schema is the complete allowlist of fields formula authors may use.

typescript
const customerRuleOptions = {
  schema: {
    Country: { type: 'string' },
    Active: { type: 'boolean' },
    'Order Total': { type: 'number' },
    CustomerName: { type: 'string' },
    OptionalCode: { type: 'string', nullable: true },
  },
  expectedResult: 'boolean',
} satisfies ExpressionOptions;

Schema design guidelines:

  • expose business-friendly names;
  • keep the schema as small as the use case allows;
  • use nullable only when NULL is a real domain value;
  • do not expose secrets or fields the author is not allowed to use;
  • version the application's schema contract together with its saved formula source.

Use { type: 'scalar' } only for fields that genuinely permit either a string or a finite number. Direct concrete-type operations on scalar fields fail validation; formula authors must use text or tryNumber explicitly.

Field descriptors and runtime records must be ordinary objects with own data properties. Materialize proxies before calling BlendScript.

Lesson 11: Validate while the author edits ​

Validation does not create retained executable state. It is suitable for an editor or syntax-check request.

typescript
function checkCustomerFormula(source: string): ValidationResult {
  return validateExpression(source, customerRuleOptions);
}

const validation = checkCustomerFormula('Country IN ("NL", "BE") AND Active');

if (!validation.ok) {
  for (const diagnostic of validation.diagnostics) {
    console.log(
      diagnostic.code +
        ' at line ' +
        diagnostic.location.line +
        ', column ' +
        diagnostic.location.column +
        ': ' +
        diagnostic.message
    );
  }
}

Use the span to highlight the failing part of the source. Use the stable code for application logic and the message for people.

Lesson 12: Save source, then compile ​

Persist source text and the application schema version. Do not persist CompiledExpression: it is an opaque, in-memory, package-instance-owned handle.

typescript
interface StoredRule {
  readonly id: string;
  readonly source: string;
  readonly schemaVersion: number;
}

const storedRule: StoredRule = {
  id: 'customer-review',
  source: 'Country IN ("NL", "BE") AND Active AND [Order Total] >= 1000',
  schemaVersion: 1,
};

const compilation = compileExpression(storedRule.source, customerRuleOptions);

if (!compilation.ok) {
  // The saved rule is no longer valid for this application schema.
  console.log(compilation.diagnostics);
}

Compile when a rule is loaded or activated, then reuse the handle. Recompile after process restart, package upgrade, source change, or schema change.

Lesson 13: Evaluate complete records ​

Every declared schema field must be present, even when the current formula does not reference it. Undeclared extra fields are ignored.

typescript
interface Customer {
  readonly country: string;
  readonly active: boolean;
  readonly orderTotal: number;
  readonly customerName: string;
  readonly optionalCode: string | null;
}

function toBlendScriptRecord(customer: Customer): Readonly<Record<string, ExpressionValue>> {
  return {
    Country: customer.country,
    Active: customer.active,
    'Order Total': customer.orderTotal,
    CustomerName: customer.customerName,
    OptionalCode: customer.optionalCode,
  };
}

function runCustomerRule(expression: CompiledExpression, customer: Customer): EvaluationResult {
  return evaluateExpression(expression, toBlendScriptRecord(customer));
}

Your application decides what TRUE, FALSE, text, number, or NULL means. BlendScript does not perform actions or modify the customer.

Lesson 14: Handle evaluation diagnostics and API errors ​

Evaluation returns a result union:

typescript
if (compilation.ok) {
  const result = runCustomerRule(compilation.expression, customer);

  if (result.ok) {
    if (result.value === true) {
      queueForReview(customer);
    }
  } else {
    reportRuleDiagnostic(result.diagnostic);
  }
}

Source diagnostics identify an operator or function in the formula. Record diagnostics identify a field without disclosing its value:

typescript
function diagnosticSummary(diagnostic: ExpressionDiagnostic): string {
  if (diagnostic.kind === 'record') {
    return diagnostic.code + ' for field ' + diagnostic.field;
  }
  return (
    diagnostic.code +
    ' at line ' +
    diagnostic.location.line +
    ', column ' +
    diagnostic.location.column
  );
}

BlendScriptApiError represents programmer misuse, not an author mistake:

typescript
try {
  validateExpression(source, customerRuleOptions);
} catch (error) {
  if (error instanceof BlendScriptApiError) {
    applicationLogger.error(error.code, error.message);
  } else {
    throw error;
  }
}

Do not show internal exceptions to formula authors.

Lesson 15: Complete framework-neutral integration ​

The following module keeps validation, compilation, and evaluation separate:

typescript
import {
  compileExpression,
  evaluateExpression,
  validateExpression,
  type CompiledExpression,
  type EvaluationResult,
  type ExpressionOptions,
  type ExpressionValue,
  type ValidationResult,
} from 'blendsdk/blendscript';

const options = {
  schema: {
    Country: { type: 'string' },
    Active: { type: 'boolean' },
    'Order Total': { type: 'number' },
    CustomerName: { type: 'string' },
    OptionalCode: { type: 'string', nullable: true },
  },
  expectedResult: 'boolean',
} satisfies ExpressionOptions;

export function validateRuleSource(source: string): ValidationResult {
  return validateExpression(source, options);
}

export function prepareRule(source: string): CompiledExpression {
  const result = compileExpression(source, options);
  if (!result.ok) {
    throw new Error('Saved BlendScript rule is invalid: ' + result.diagnostics[0].code);
  }
  return result.expression;
}

export function evaluateRule(
  expression: CompiledExpression,
  record: Readonly<Record<string, ExpressionValue>>
): EvaluationResult {
  return evaluateExpression(expression, record);
}

An application can connect these functions to any UI, HTTP endpoint, job worker, or event consumer:

  • the authoring endpoint calls validateRuleSource;
  • the save operation stores source only after successful validation;
  • application startup or rule activation calls prepareRule once;
  • record processing calls evaluateRule many times;
  • business code handles the returned value.

Lesson 16: Production integration checklist ​

  • Install blendsdk and import from blendsdk/blendscript.
  • Define one explicit schema per rule context.
  • Use scalar for string-or-number source fields and convert them explicitly in formulas.
  • Require expectedResult when the host expects a specific result type.
  • Validate source before saving it.
  • Store source and an application schema version, not the compiled handle.
  • Compile after load and reuse the handle.
  • Supply every schema field as an own data property.
  • Materialize proxies and validate external JSON at the host boundary.
  • Separate author diagnostics from BlendScriptApiError programmer failures.
  • Keep authorization and sensitive-field decisions in the host application.
  • Test valid, invalid, boundary, Unicode, blank, null, and wrong-record cases.
  • Revalidate and recompile saved rules after schema or package upgrades.

Exercises ​

Exercise 1: Translate a requirement ​

Write a rule for: “The customer is active, is in NL or DE, and is not blocked.”

Available fields: Active, Country, Blocked.

Exercise 2: Predict precedence ​

What does this mean?

text
Gold == TRUE OR OrderTotal >= 5000 AND Blocked == FALSE

Add parentheses so Gold or the large-order condition is selected first, and Blocked must always be FALSE.

Exercise 3: Correct the formula ​

text
=Customer Name = 'Ada'

The actual schema field is Customer Name.

Exercise 4: Choose the API ​

Choose validateExpression, compileExpression, or evaluateExpression for each action:

  1. Show errors while an author types.
  2. Prepare a saved rule when the application starts.
  3. Run the prepared rule for 10,000 customer records.

Exercise 5: Explain the data error ​

The schema declares Country, Active, and CustomerName. A rule references only Active. The record contains only Active. What happens?

Answer key ​

Answer 1 ​

text
Active AND Country IN ("NL", "DE") AND NOT Blocked

Answer 2 ​

The original expression means Gold is TRUE, or both the order is at least 5,000 and the customer is not blocked. To require not blocked for both alternatives:

text
(Gold == TRUE OR OrderTotal >= 5000) AND Blocked == FALSE

Answer 3 ​

text
[Customer Name] == "Ada"

Remove the leading equals sign, bracket the spaced field name, use ==, and use double-quoted text.

Answer 4 ​

  1. validateExpression
  2. compileExpression
  3. evaluateExpression using the same compiled handle

Answer 5 ​

Evaluation returns BS_MISSING_FIELD for Country before interpreting the expression. Every schema field must be present in every record, including unreferenced fields.
