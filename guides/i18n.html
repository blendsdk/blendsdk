Overview ​

In this guide, you'll learn how to implement internationalization (i18n) in your application using the BlendSDK's i18n package. We'll cover setting up translation catalogs, using different translation sources like JSON files and PostgreSQL databases, resolving user locales, and managing dynamic content translations. By the end of this tutorial, you'll have a fully functional multi-language environment capable of serving localized content based on user preferences.

Prerequisites ​

Before getting started, ensure you have the following prerequisites:

  • Basic understanding of TypeScript
  • A working environment with Node.js installed
  • Familiarity with web application development

Translator and TranslationCatalog Setup ​

The core of BlendSDK's i18n implementation is the Translator and TranslationCatalog. We'll begin by setting up a basic Translator with an in-memory catalog for simple translations.

typescript
import { Translator } from 'blendsdk/i18n/types';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en: 'Hello ${name}', nl: 'Hallo ${name}' },
        farewell: { en: 'Goodbye', nl: 'Tot ziens' },
    },
});

// Translate a greeting message into English
const message = translator.translate('greeting', 'en', { name: 'Alice' });
console.log(message); // Output: Hello Alice

JSON File Translation Source ​

Next, we'll extend our setup to use a JsonFileSource for loading translations from JSON files. This is useful for managing translations outside of your codebase.

typescript
import { JsonFileSource } from 'blendsdk/i18n/node';

const jsonSource = new JsonFileSource({
    paths: ['./translations/*.json'], // Directory containing translation JSON files
});

async function loadJsonTranslations() {
    try {
        const catalog = await jsonSource.load();
        console.log(catalog);
    } catch (error) {
        console.error('Failed to load translations from JSON files:', error);
    }
}

// Invoking the load function to print the catalog
loadJsonTranslations();

Content File Source (HTML/MD/TXT per Locale) ​

Adding support for content files, such as HTML or Markdown, involves using the ContentFileSource. This is especially useful for emails or web pages that require localization.

typescript
import { ContentFileSource } from 'blendsdk/i18n/node';

const contentSource = new ContentFileSource({
    paths: ['./content/emails'], // Directory for content files
    extensions: ['.html', '.md'], // Supported file types
});

async function loadContentTranslations() {
    try {
        const catalog = await contentSource.load();
        console.log(catalog);
    } catch (error) {
        console.error('Failed to load translations from content files:', error);
    }
}

loadContentTranslations();

Locale Fallback Chain: Exact → Language-Only → Default ​

BlendSDK's i18n supports a fallback chain for locale resolution. If a specific locale is unavailable, it falls back to a more general one, and finally to a default.

typescript
import { Translator } from 'blendsdk/i18n';

const translator = new Translator({
    defaultLocale: 'en',
    catalog: {
        greeting: { en_GB: 'Hello, mate!', en: 'Hello' },
    },
});

console.log(translator.translate('greeting', 'en_GB')); // Output: Hello, mate!
console.log(translator.translate('greeting', 'nl'));    // Output: Hello (using default en)

Catalog Merging from Multiple Sources ​

BlendSDK allows merging multiple translation sources into a single catalog. This is key in managing translations stored in different types of storage.

typescript
import { mergeCatalogs } from 'blendsdk/i18n';
import { JsonFileSource, ContentFileSource } from 'blendsdk/i18n/node';

async function loadAndMergeTranslations() {
    const jsonSource = new JsonFileSource({ paths: ['./translations/*.json'] });
    const contentSource = new ContentFileSource({ paths: ['./content/emails'], extensions: ['.html'] });

    try {
        const [jsonCatalog, contentCatalog] = await Promise.all([
            jsonSource.load(),
            contentSource.load(),
        ]);

        const mergedCatalog = mergeCatalogs([jsonCatalog, contentCatalog]);
        console.log(mergedCatalog);
    } catch (error) {
        console.error('Error during catalog loading:', error);
    }
}

loadAndMergeTranslations();

WebAFX i18n Plugin for Automatic Locale Resolution ​

Install and configure the WebAFX i18n plugin to automate locale resolution in your web applications.

typescript
import { createI18nPlugin, jsonFileSource } from 'blendsdk/webafx-i18n';
import { WebApplication } from 'blendsdk/webafx';

const app = new WebApplication();

app.use(createI18nPlugin({
    defaultLocale: 'en',
    sources: [
        jsonFileSource({ paths: ['./translations/*.json'] }),
    ],
}));

app.start();

PostgreSQL Translation Source for Dynamic Content ​

import { createI18nPlugin, postgresqlSource } from 'blendsdk/webafx-i18n';
import { WebApplication } from 'blendsdk/webafx';

const app = new WebApplication();

// Configure database connection for translations
app.use(createI18nPlugin({
    defaultLocale: 'en',
    sources: [
        postgresqlSource({
            queryFn: async (sql) => {
                // Replace this with actual database connection and query
                return await database.query(sql);
            },
        }),
    ],
}));

app.start();
