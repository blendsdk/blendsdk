Introduction ​

In this guide, we will explore how to set up and configure structured logging using the blendsdk/webafx-pino package integrated with Pino for BlendSDK web applications. You will learn how to configure the logger for both development and production environments, handle request and response logging, and ensure sensitive data is properly redacted. By the end of this guide, you will have a production-ready logging setup in your BlendSDK application with the ability to adjust log levels dynamically.

Prerequisites ​

Before starting, ensure you have the following:

  • Node.js installed on your machine
  • TypeScript set up in your development environment
  • A basic understanding of Express.js and middleware
  • BlendSDK installed in your project

Set Up Pino Logger ​

To begin, you'll need to install the blendsdk/webafx-pino package:

bash
npm install blendsdk/webafx-pino

Basic Logger Initialization ​

Create a basic logger instance using PinoLoggerProvider:

typescript
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';

async function main() {
  const logger = new PinoLoggerProvider({ level: 'info', pretty: true });
  await logger.info('Logger initialized');
  await logger.shutdown();
}

main().catch((error) => console.error('Error:', error));

This initialization sets up the logger with info level logging, with pretty-printing enabled for easier reading during development.

Structured Logging with Context ​

Structured logging allows you to include context with your log messages, which is useful for debugging and analytics.

Logging Messages with Context ​

Here's how you can log messages with additional structured data:

typescript
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';

async function main() {
  const logger = new PinoLoggerProvider({ level: 'info' });
  await logger.info('User action recorded', { userId: 123, action: 'login' });
  await logger.shutdown();
}

main().catch((error) => console.error('Error:', error));

Request/Response Logging Middleware ​

To log each request and response in your Express.js application, integrate the logger as middleware:

typescript
import express from 'express';
import { pinoLoggerPlugin } from 'blendsdk/webafx-pino';

const app = express();

// Integrate logger plugin as middleware
app.use(pinoLoggerPlugin({ level: 'info' }));

app.get('/', async (req, res) => {
  await req.log.info('Homepage accessed', { route: '/' });
  res.send('Hello World');
});

app.listen(3000, () => {
  console.log('Server running on port 3000');
});

This setup ensures that every request handled by your application is logged with the request-specific context.

Log Levels and Filtering ​

The PinoLoggerProvider allows you to set different log levels, which control the verbosity of log output.

Dynamic Log Level Control ​

You can manage log levels dynamically using environment variables:

typescript
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';

async function main() {
  const currentLogLevel = process.env.LOG_LEVEL || 'info';
  const logger = new PinoLoggerProvider({ level: currentLogLevel });

  await logger.info('Application started', { level: currentLogLevel });
  await logger.shutdown();
}

main().catch((error) => console.error('Error:', error));

Production vs Development Logging Formats ​

In development, pretty-printed logs are useful for readability. In production, JSON structured logs are preferred for performance and automated processing.

Configure Pretty Printing ​

Enable pretty-printing for development as follows:

typescript
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';

const logger = new PinoLoggerProvider({
  level: 'info',
  pretty: process.env.NODE_ENV !== 'production'
});

WebAFX Logger Interface Adapter ​

The PinoLoggerProvider is seamlessly integrated with the BlendSDK Logger interface, which ensures compatibility with other BlendSDK components. It also provides lifecycle management methods like shutdown() to ensure that all logs are flushed before the application exits, preventing data loss.

Full Application Example ​

Combine all the features to create a full example:

typescript
import express from 'express';
import { pinoLoggerPlugin, PinoLoggerProvider } from 'blendsdk/webafx-pino';

async function main() {
  const app = express();
  const logger = new PinoLoggerProvider({
    level: process.env.LOG_LEVEL || 'info',
    pretty: process.env.NODE_ENV !== 'production',
    redact: ['req.headers.authorization']
  });

  app.use(pinoLoggerPlugin({ logger }));

  app.get('/', async (req, res) => {
    await req.log.info('Homepage accessed', { route: '/' });
    res.send('Hello World');
  });

  app.listen(3000, () => {
    console.log('Server running on port 3000');
  });
}

main().catch((error) => console.error('Error:', error));
