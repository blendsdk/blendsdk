Introduction ​

In this guide, we will walk through the process of setting up a production-ready REST API using the BlendSDK web framework. We'll cover everything from initial setup to implementing structured logging with webafx-pino. By the end, you'll have a complete example of a REST API ready for production use.

Prerequisites ​

Before proceeding, make sure you have the following:

  • Node.js installed on your system (version 16 or higher is recommended)
  • A basic understanding of TypeScript and RESTful API concepts
  • Familiarity with Express.js and middleware

Setting Up an Express 5 Application ​

First, we need to set up a basic Express application using the blendsdk/webafx web framework. We'll start with installing the necessary packages.

bash
npm install blendsdk

Now, create a file app.ts where we'll configure our web application.

typescript
import { WebApplication } from 'blendsdk/webafx';
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';

async function main() {
  const app = new WebApplication({ PORT: 3000 });
  const logger = new PinoLoggerProvider({ level: 'info', pretty: true });

  app.start().then(() => logger.info('Server is running on port 3000'));

  // Gracefully shutdown the server
  const shutdown = async () => {
    await app.shutdown();
    await logger.shutdown();
    process.exit(0);
  };

  process.on('SIGINT', shutdown);
  process.on('SIGTERM', shutdown);
}

main().catch((error) => console.error('Error:', error));

With this configuration, our server is now configured to start on port 3000 and handle graceful shutdowns.

Implementing Routing and Route Builders ​

In BlendSDK, routes are defined using controllers. Let's create a simple controller to handle API routes.

typescript
import { BaseController, RouteBuilder } from 'blendsdk/webafx';
import { Request, Response } from 'express';

class HelloWorldController extends BaseController {
  routes() {
    return [
      new RouteBuilder()
        .get('/')
        .handle(this.helloWorld),
    ];
  }

  async helloWorld(req: Request, res: Response) {
    this.ok(res, { message: 'Hello, World!' });
  }
}

export default HelloWorldController;

Register this controller within our application setup:

typescript
app.registerController('/', HelloWorldController);

Routes opt into OpenAPI generation by chaining .openapi() before .handle(). Only annotated routes appear in the generated contract; a route without it stays hidden. The OidcAuthController in blendsdk/webafx-auth, for example, documents its five BFF routes — login, callback, me, refresh, and logout — this way under the oidc tag, including the csrf_invalid 403 response that logout and refresh return when CSRF enforcement is on. See API Client for annotating your own routes and Authentication for the flow.

Controllers and BaseController Patterns ​

Controllers derive from BaseController, allowing route organization and middleware application. Methods like ok, created, and noContent simplify sending HTTP responses.

Here's an extended example of a User Controller:

typescript
import { BaseController } from 'blendsdk/webafx';
import { Request, Response } from 'express';

class UserController extends BaseController {
  routes() {
    return [
      this.route()
        .get('/users')
        .handle(this.getUsers),
    ];
  }

  async getUsers(req: Request, res: Response) {
    const users = [{ id: 1, name: 'John Doe' }];
    this.ok(res, users);
  }
}

export default UserController;

Adding Middleware and Request Processing ​

Middleware can be used for processing requests, e.g., validation or authentication.

typescript
import { Request, Response, NextFunction } from 'express';

const requestLogger = (req: Request, res: Response, next: NextFunction) => {
  console.log(`[${new Date().toISOString()}] ${req.method} ${req.url}`);
  next();
};

app.express.use(requestLogger);

Dependency Injection with ServiceContainer ​

The ServiceContainer allows us to manage and inject dependencies.

typescript
import { ServiceContainer } from 'blendsdk/webafx';

class MyService {
  log(message: string) {
    console.log(message);
  }
}

app.services.registerSingleton<MyService>('myService', () => new MyService());

app.services.get<MyService>('myService')?.log('Service started');

Plugin System Integration ​

Plugins enhance functionality, such as logging with webafx-pino.

typescript
import { pinoLoggerPlugin } from 'blendsdk/webafx-pino';

app.use(pinoLoggerPlugin({ level: 'info', pretty: true }));

Structured Logging with Pino ​

Structured logging provides detailed context, improving debugging and monitoring.

typescript
const structuredLogger = new PinoLoggerProvider({
  level: 'info',
  redact: ['req.headers.authorization'],
});

Error Handling and Validation ​

Handle errors consistently across the application using error handling middleware.

typescript
import { errorHandlerMiddleware } from 'blendsdk/webafx';

app.express.use(errorHandlerMiddleware(async (req, error) => {
  console.error('Caught error:', error);
}, true));

Complete Example ​

Finally, compile everything into a single cohesive application:

typescript
import { WebApplication } from 'blendsdk/webafx';
import { PinoLoggerProvider } from 'blendsdk/webafx-pino';
import HelloWorldController from './HelloWorldController';
import UserController from './UserController';

async function main() {
  const app = new WebApplication({ PORT: 3000 });
  const logger = new PinoLoggerProvider({ level: 'info', pretty: true });

  app.registerController('/hello', HelloWorldController);
  app.registerController('/api', UserController);
  app.use(pinoLoggerPlugin({ level: 'info' }));

  await app.start().then(() => logger.info('Server is running on port 3000'));
  
  const shutdown = async () => {
    await app.shutdown();
    await logger.shutdown();
    process.exit(0);
  };

  process.on('SIGINT', shutdown);
  process.on('SIGTERM', shutdown);

}

main().catch((error) => console.error('Error:', error));
