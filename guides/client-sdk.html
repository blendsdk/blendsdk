API Client ​

The typed API client turns the routes you already wrote in WebAFX into a small TypeScript SDK. One command reads the .openapi() metadata on your controllers, writes a committed OpenAPI contract, and emits a client whose methods match your routes.

Use it when more than one caller needs your API:

  • A browser app wants typed methods such as client.products.getProduct({ id: 42 }) instead of hand-written fetch calls.
  • A Node service authenticates machine-to-machine and calls the same API with the same types.

The client is generated from the server, so when you rename a field on a controller the client stops compiling. That compile error is the point: the drift is caught before it reaches a user, not after a request fails.

The runtime lives in blendsdk/api-client. It has no dependencies and does not import Zod, so it is safe to ship to a browser. The generator lives in blendsdk/codegen and runs only on your machine or in CI.

Annotate controllers with .openapi() ​

Only routes that call .openapi() are collected into the contract. A route without it stays hidden, so your internal endpoints never leak into the public client.

typescript
import { BaseController, NotFoundError } from 'blendsdk/webafx';
import { Request, Response } from 'express';
import { z } from 'zod';

const productSchema = z.object({
  id: z.number(),
  name: z.string(),
  price: z.number(),
});

const errorSchema = z.object({
  success: z.boolean(),
  error: z.object({ message: z.string(), statusCode: z.number() }),
});

export class ProductsController extends BaseController {
  routes() {
    return [
      this.route()
        .get('/:id')
        .openapi({
          summary: 'Get product by ID',
          tags: ['products'],
          operationId: 'getProduct',
          pathParams: {
            id: { schema: z.coerce.number().int().min(1), description: 'Product ID' },
          },
          responses: [
            { statusCode: 200, description: 'Product details', schema: productSchema },
            { statusCode: 404, description: 'Product not found', schema: errorSchema },
          ],
        })
        .handle(this.getProduct),
    ];
  }

  async getProduct(req: Request, res: Response) {
    const { id } = req.services.getParams<{ id: number }>();
    const product = await loadProduct(id);
    if (!product) {
      throw new NotFoundError(`Product ${id} not found`);
    }
    this.ok(res, product);
  }
}

The fields you will use most:

FieldPurpose
operationIdThe generated method name. It must be unique across the whole API.
tagsThe generated namespace. The first tag wins, so ['products'] becomes client.products.
pathParamsZod schemas for :param segments the validation schema does not already describe.
responsesThe status codes and their response schemas. The first 2xx schema becomes the result type.
envelopeHow the client reads the body. Defaults to 'data'.

Use .validate(schema) for query and body fields, and keep pathParams for the :param pieces. Together they become one typed params object on the client.

Choose the response envelope ​

Almost every WebAFX success response is wrapped as { success: true, data }. The default envelope: 'data' returns just the data value, which is what you want for a single object.

A paginated route also carries a pagination object, so it must keep the whole body. Set envelope: 'body' and let the client expose the pagination metadata:

typescript
this.route()
  .get('/')
  .openapi({
    summary: 'List products',
    tags: ['products'],
    operationId: 'listProducts',
    envelope: 'body',
    responses: [
      // This schema describes one product. The client wraps it in PaginatedResponse<T>.
      { statusCode: 200, description: 'One product', schema: productSchema },
    ],
  })
  .validate(listQuerySchema)
  .handle(this.listProducts);

A paginated handler usually calls this.paginated(res, items, total, page, limit), which sends { success: true, data: items, pagination: { total, page, limit, pages } }.

Describe the contract in blendsdk.api.ts ​

Create one blendsdk.api.ts file at your project root. It names the controllers to collect and where the generated artifacts go, and it is the single source of truth for both.

typescript
import { defineApiContract } from 'blendsdk/codegen';
import { ProductsController } from './src/controllers/products-controller.js';

export default defineApiContract({
  outputDir: 'src/api-client',
  contractFile: 'api.json',
  controllers: [{ basePath: '/api/products', controller: ProductsController }],
  openapi: {
    title: 'My API',
    version: '1.0.0',
    servers: [{ url: 'http://localhost:3000', description: 'Local development server' }],
    securitySchemes: {
      bearerAuth: { type: 'http', scheme: 'bearer', bearerFormat: 'JWT' },
    },
    defaultSecurity: [{ bearerAuth: [] }],
  },
  generator: { runtimeImport: 'blendsdk/api-client' },
});
OptionMeaning
outputDirDirectory for the generated client, resolved relative to the config file. It must not escape that directory.
contractFileThe committed OpenAPI JSON. Defaults to api.json, resolved relative to the config file.
controllersThe { basePath, controller } list. Use the same basePath you pass to app.registerController().
openapiThe document metadata and security schemes shown in the contract.
generator.runtimeImportThe import specifier the generated client uses. Defaults to blendsdk/api-client.

The CLI finds this file through --config <path>, or by searching upward from the current directory for blendsdk.api.ts until it reaches the repository root.

Generate and check from the CLI ​

bash
blendsdk api generate --config blendsdk.api.ts   # rebuild api.json, then write the client
blendsdk api check --config blendsdk.api.ts      # fail if the committed artifacts drifted

generate rebuilds the OpenAPI document from the controllers, writes the contract JSON, and writes the client. Commit blendsdk.api.ts, api.json, and the generated directory together.

check does the same rebuild in memory, compares it against the committed files, and writes nothing. It needs no database and no running server, so it belongs in CI:

bash
# In your CI job, after installing dependencies.
blendsdk api check --config blendsdk.api.ts

Exit codes tell you what happened:

Exit codeMeaning
0Clean: the committed artifacts match the controllers.
1Drift, or an operational failure such as a missing file.
2Usage or configuration failure, such as a bad --config value.

A 1 from check means a controller changed but the committed artifacts did not. Run generate, review the diff, and commit it.

What the generator writes ​

Three files land in outputDir. Each starts with a marker line that tells the generator what it owns, so you should not edit them by hand.

  • types.ts holds the request params and result types, one pair per operation.
  • client.ts holds the typed client and its factory.
  • index.ts re-exports both, so consumers import from a single path.
typescript
// src/api-client/types.ts (generated — do not edit)
export type ProductsGetProductParams = { id: number };

export type ProductsGetProductResult = {
  id: number;
  name: string;
  price: number;
};

// For an `envelope: 'body'` route the result is wrapped:
export type ProductsListProductsResult = PaginatedResponse<{
  id: number;
  name: string;
  price: number;
}>;

The factory groups every method by its first tag:

typescript
// src/api-client/client.ts (generated — do not edit)
export interface AppClient {
  products: {
    getProduct: (
      params: ProductsGetProductParams,
      options?: RequestOptions
    ) => Promise<ProductsGetProductResult>;
    listProducts: (
      params: ProductsListProductsParams,
      options?: RequestOptions
    ) => Promise<ProductsListProductsResult>;
  };
}

export function createAppClient(options: ApiClientOptions): AppClient {
  const runtime = createApiClient(options);
  return {
    products: {
      // one method per operation, each forwarding a flat params object
    },
  };
}

ApiClientOptions and RequestOptions come from blendsdk/api-client. Set generator.splitByGroup: true to write one client.<group>.ts file per tag and make client.ts the barrel instead.

Consuming the client ​

Import the factory from the generated index.ts. The params and the result are typed from the contract, so a server-side rename fails the client build.

typescript
import { createAppClient } from './api-client/index.js';

const client = createAppClient({ baseUrl: 'http://localhost:4000' });

// GET /api/products/42, `envelope: 'data'` -> the product object itself
const product = await client.products.getProduct({ id: 42 });
console.log(product.name); // typed as string

createAppClient accepts baseUrl, plus the optional auth, headers, and adapter options of createApiClient. Every method also takes a last options argument to override things for one call, such as signal to cancel it.

Read a paginated response ​

For an operation declared with envelope: 'body', the result type is PaginatedResponse<T>, where T is the item type in data. Both data and pagination survive the unwrapping.

typescript
import type { PaginatedResponse } from 'blendsdk/api-client';

const page = await client.products.listProducts({ page: 1, limit: 20 });

console.log(page.success); // true
console.log(page.data.length); // items on this page
console.log(page.pagination.total); // items across all pages
console.log(page.pagination.page, 'of', page.pagination.pages);

PaginatedResponse<T> is { success: true; data: T[]; pagination: { total; page; limit; pages } }. The runtime owns this type, so a browser client never imports the server package.

Handle errors ​

A non-2xx response becomes an ApiError. A failure that happens before a response exists, such as a network error or an abort, becomes an ApiTransportError. Branch on the machine-readable code, not on the message text, because messages come from the server and can change.

typescript
import { ApiError, ApiTransportError } from 'blendsdk/api-client';

try {
  const product = await client.products.getProduct({ id: 42 });
  console.log(product.name);
} catch (error) {
  if (error instanceof ApiError) {
    console.error(error.statusCode, error.code, error.message);
    // 404 not_found Product 42 does not exist
  } else if (error instanceof ApiTransportError) {
    console.error('transport failure in', error.operationId, error.message);
  } else {
    throw error;
  }
}
ClassKey fields
ApiErrorstatusCode, code, message, details, requestId, operationId
ApiTransportErrormessage, operationId, cause

Both classes are already redacted: credentials are stripped before they reach your handler.

Authentication ​

Pass one AuthStrategy when you create the client, and the runtime applies it to every request. You can also override it per call through the options argument.

StrategySchemeWhen to use it
CookieSessionAuthcookieBrowser apps that own a session cookie.
ApiKeyAuthapiKeyServer-to-server calls with a static key.
BearerAuthbearerAuthA token you hold in memory, with optional refresh.
OidcClientCredentialsAuthoauth2Node machine-to-machine jobs that fetch tokens from an identity provider.

CookieSessionAuth only tells the request to include the browser credentials. The server stays responsible for the cookie's SameSite attribute and for CSRF protection.

typescript
import { CookieSessionAuth } from 'blendsdk/api-client';

const client = createAppClient({ baseUrl: '/api', auth: new CookieSessionAuth() });

ApiKeyAuth sends the key in X-API-Key by default; pass name to use a different header. Sending it in the query string is an explicit opt-in that warns, because query strings are commonly logged.

typescript
import { ApiKeyAuth } from 'blendsdk/api-client';

const client = createAppClient({
  baseUrl: 'https://api.example.com',
  auth: new ApiKeyAuth({ key: process.env.API_KEY! }),
});

BearerAuth calls getToken for the current token. When you also provide refresh, the runtime retries one 401 with a fresh token, and concurrent 401s share a single refresh. Call auth.invalidate() on logout to drop the cached token.

typescript
import { BearerAuth } from 'blendsdk/api-client';

const auth = new BearerAuth({
  getToken: () => session.accessToken,
  refresh: () => session.refresh(),
});

const client = createAppClient({ baseUrl: '/api', auth });

OidcClientCredentialsAuth implements the OAuth 2.0 client-credentials grant. It is Node-only: the constructor throws in a browser or a worker, so a client secret can never be shipped to a browser by accident. The token endpoint must use HTTPS; plain HTTP is allowed only for a loopback endpoint such as localhost.

typescript
import { OidcClientCredentialsAuth } from 'blendsdk/api-client';

const auth = new OidcClientCredentialsAuth({
  tokenEndpoint: process.env.IDP_TOKEN_URL!,
  clientId: process.env.IDP_CLIENT_ID!,
  clientSecret: process.env.IDP_CLIENT_SECRET!,
  scope: 'api.read',
});

const client = createAppClient({ baseUrl: 'https://api.example.com', auth });
