Introduction ​

In this guide, you will learn how to implement authentication in a WebAFX application using BlendSDK's webafx-auth package. We will cover topics such as JWT validation, OAuth2 introspection, OIDC discovery, multi-tenant authentication routing, the authorization code flow with PKCE, and cookie-based session management. By the end of this tutorial, you will have a comprehensive understanding of how to secure a web application using these mechanisms.

Prerequisites ​

Before you begin, ensure you have the following:

  • A working knowledge of TypeScript
  • An environment set up with Node.js and npm
  • Basic understanding of authentication concepts
  • BlendSDK installation
  • A configured WebAFX application

Setting Up the Environment ​

First, you need to install the BlendSDK authentication package:

bash
npm install blendsdk

or

bash
yarn add blendsdk

JWT Validation with JwtAuthProvider ​

The first step in securing your application is to set up a basic JWT validation mechanism. Here's how to configure the JwtAuthProvider to validate tokens against a hardcoded secret.

typescript
import { JwtAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

// Initialize the Express application
const app = express();

// Setup JwtAuthProvider
const jwtProvider = new JwtAuthProvider({
    secret: 'my-secret-key',
    algorithms: ['HS256'],
    issuer: 'https://api.example.com',
    audience: 'my-client-id',
});

// Middleware to validate JWT
app.use(async (req, res, next) => {
    const token = req.headers['authorization']?.split(' ')[1];
    if (!token) return res.status(401).send('Unauthorized');

    try {
        const authResult = await jwtProvider.validate(token);
        if (!authResult) return res.status(401).send('Unauthorized');

        // Attach user information to the request
        req.user = authResult;
        next();
    } catch (error) {
        return res.status(500).json({ error: 'Internal Server Error' });
    }
});

app.get('/protected', (req, res) => {
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

Multi-Tenant Authentication ​

In scenarios where you support multi-tenant authentication, a provider's per-request configFactory supplies the tenant-specific settings. No built-in tenant provider ships with the package; the example below configures an OIDC provider that adjusts to the tenant's domain. The package also exports tenant delegation contracts (TenantAuthConfig, TenantResolver, TenantProviderFactory) if you prefer to compose your own tenant-aware provider.

typescript
import { OidcAuthProvider } from 'blendsdk/webafx-auth';
import express from 'express';

// Initialize the Express application
const app = express();

// Setup OIDC provider for multi-tenant
const provider = new OidcAuthProvider({
    serviceName: 'multi-tenant',
    configFactory: async (req) => {
        const tenantId = req.headers['x-tenant-id']; // Extract tenant ID

        return {
            issuerUrl: `https://auth.${tenantId}.example.com`,
            clientId: `${tenantId}-client`,
            clientSecret: `${tenantId}-secret`,
            redirectUri: `https://app.${tenantId}.example.com/callback`,
        };
    },
});

// Middleware to authenticate requests for multiple tenants
app.use(async (req, res, next) => {
    try {
        const result = await provider.authenticate(req);
        if (!result) return res.status(401).send('Unauthorized');

        req.user = result;
        next();
    } catch (error) {
        return res.status(401).json({ error: 'Unauthorized' });
    }
});

app.get('/protected', (req, res) => {
    res.send(`Hello ${req.user.sub}`);
});

app.listen(3000, () => {
    console.log('Server running on http://localhost:3000');
});

OIDC Authorization Code Flow with PKCE ​

To implement the OIDC flow with PKCE in your application, first set up the login and callback endpoints. This flow allows secure authentication and session management.

Building the Authorization URL ​

typescript
import express from 'express';
import { OidcAuthProvider } from 'blendsdk/webafx-auth';

const app = express();

const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
});

// Endpoint to trigger login
app.get('/auth/login', async (req, res) => {
    try {
        // Build the authorization URL
        const authUrlResult = await provider.buildAuthorizationUrl();
        res.redirect(authUrlResult.url);
    } catch (error) {
        console.error('Error building auth URL:', error);
        res.status(500).send('Internal Server Error');
    }
});

Handling the Callback ​

typescript
// Callback endpoint
app.get('/callback', async (req, res) => {
    try {
        const tokens = await provider.exchangeCode({
            codeVerifier: 'verifier-from-client',
            callbackUrl: 'https://yourapp.com/callback?code=' + req.query.code,
        });

        // Store session secure cookies
        res.cookie('session_id', tokens.accessToken, {
            httpOnly: true,
            secure: true,
        });

        res.send('Logged in successfully');
    } catch (error) {
        console.error('Error during token exchange:', error);
        res.status(401).send('Unauthorized');
    }
});

Hardening the OIDC Flow ​

The authorization code flow works with safe defaults. The options below adapt it to private infrastructure and add the controls a production deployment usually needs. All of them are opt-in, so an existing configuration keeps its current behavior until you set them.

Transport Security ​

By default the OIDC provider calls the issuer over HTTPS and validates its certificate against the system trust store. Two fields inside transport cover the exceptions:

  • ca — a PEM certificate bundle to trust. It replaces the system roots, so include the public roots in the same value when you need both.
  • allowInsecureRequests — permits non-HTTPS issuers and disables certificate validation. Use it only for local development or a test issuer. When it is enabled the provider logs a warning once per provider instance.
typescript
import { OidcAuthProvider } from 'blendsdk/webafx-auth';
import fs from 'node:fs';

const provider = new OidcAuthProvider({
    issuerUrl: 'https://idp.internal.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
    transport: {
        // Trust a private CA; include the public roots too if you need both.
        ca: fs.readFileSync('./certs/internal-ca.pem', 'utf8'),
        // allowInsecureRequests: true, // development only
    },
});

transport is read from the static configuration only. A per-request configFactory cannot change it.

ID-Token Signature Verification ​

When the callback exchanges the authorization code, the provider verifies the returned ID token's signature against the issuer's published JWKS. This is the check that makes the ID token non-repudiable, and it is on by default.

Set verifyIdTokenSignature to false only for an issuer that cannot expose a verifiable ID token. The iss, aud, nonce, and exp claims are still validated without it.

typescript
const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
    verifyIdTokenSignature: false, // opt out of the non-repudiation check only
});

Absolute Session Lifetime ​

sessionTtl is a sliding window: every refresh can extend it. When you need a hard ceiling on how long a session may live regardless of activity, set sessionAbsoluteTtl in seconds. The provider stamps createdAt on the first store and preserves it across refreshes and session-id rotation, so the deadline never moves.

A session stored before you configured sessionAbsoluteTtl has no createdAt. The provider treats such a legacy session as created now and stamps it on the next store, rather than signing the user out. A value of 0 or less makes every session immediately expired, so use a positive value.

typescript
const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
    sessionStore: cacheProvider,   // from blendsdk/webafx-cache
    sessionTtl: 3600,              // sliding: refreshed by activity
    sessionAbsoluteTtl: 28800,     // hard cap: 8 hours in total
});

sessionAbsoluteTtl is static configuration. A per-request configFactory cannot vary it.

CSRF for the OIDC Browser Flow ​

The logout and refresh routes change state but are reached through the session cookie, which the browser sends automatically. Enable the csrf block to require a per-session token on those requests:

  • enabled — turn enforcement on. Default false.
  • header — the header carrying the token. Default 'x-csrf-token'.

The token is generated per session and returned by GET /me. It is never placed in a script-readable cookie, so the browser client must hold it in memory and send it on POST /logout and POST /refresh. A missing or wrong token is rejected with 403 and error code csrf_invalid.

typescript
const provider = new OidcAuthProvider({
    issuerUrl: 'https://auth.example.com',
    clientId: 'client-id',
    clientSecret: 'client-secret',
    redirectUri: 'https://yourapp.com/callback',
    sessionStore: cacheProvider,
    csrf: {
        enabled: true,
        header: 'x-csrf-token',
    },
});

Enforcement is static configuration. Enabling it on an application that already has sessions signs those sessions out on their next logout or refresh, because they were created without a token. When rotateSessionIdOnRefresh is enabled too, each successful refresh mints a new token and returns it in the refresh response, so the client should replace its stored copy.

Per-Request Configuration ​

For multi-tenant deployments, the provider's configFactory resolves the issuer and client credentials per request. The controller's resolveConfig(req, provider) hook drives this: by default it delegates to the provider, which calls the factory and falls back to the static configuration when none is set. Override the hook when a tenant needs custom resolution.

typescript
import { OidcAuthController, OidcAuthProvider } from 'blendsdk/webafx-auth';
import type { Request } from 'express';

class MyAuthController extends OidcAuthController {
    protected getRoutePrefix(): string {
        return '/api/oidc';
    }

    protected async resolveConfig(req: Request, provider: OidcAuthProvider) {
        // Default behavior: use the provider's configFactory when configured.
        return provider.resolveRequestConfig(req);
    }
}

Per-request resolution covers the issuer and client credentials, and other request-scoped validation settings such as the audience. Security settings such as transport, sessionAbsoluteTtl, verifyIdTokenSignature, csrf, and rotateSessionIdOnRefresh are read from the static configuration only and cannot vary per request.

CSRF for Non-OIDC Routes ​

The OIDC csrf option above applies only to the controller's logout and refresh routes. For your own cookie-authenticated routes, use csrfMiddleware or csrfPlugin from blendsdk/webafx:

typescript
import { csrfPlugin } from 'blendsdk/webafx';

// getSession returns your server-side session for the request.
app.use(csrfPlugin({
    expectedToken: (req) => getSession(req)?.csrfToken,
}));

csrfMiddleware applies to the routes you attach it to; csrfPlugin installs it application-wide before controllers are registered. Both compare the header against a session-bound token (expectedToken) or a double-submit cookie (cookie: { name }), skip safe methods (GET, HEAD, OPTIONS) by default, and reject with 403 and the code csrf_invalid.

Composable Auth Provider Configuration ​

Build a robust authentication mechanism with a composable authentication provider configuration, allowing seamless switching between environments (e.g., testing and production).

typescript
import { MemoryAuthProvider, JwtAuthProvider } from 'blendsdk/webafx-auth';

const environment = process.env.NODE_ENV || 'production';

const provider = environment === 'test'
    ? new MemoryAuthProvider({
        validTokens: {
            'test-token': {
                sub: 'test-user',
                claims: {},
                token: 'test-token',
            },
        },
    })
    : new JwtAuthProvider({
        secret: 'my-secret-key',
        algorithms: ['HS256'],
    });

// Express app setup to use the provider
const app = express();
app.use(async (req, res, next) => {
    let authResult;
    try {
        const token = req.headers['authorization']?.split(' ')[1];
        authResult = token ? await provider.validate(token) : undefined;
    } catch (error) {
        console.error('Authentication Error:', error.message);
        return res.status(401).json({ error: 'Unauthorized' });
    }
    if (!authResult) return res.status(401).send('Unauthorized');
    req.user = authResult;
    next();
});
